# Session Sync

[English](README.md) | 中文

## 概述

`@deepseek-ai/dsh-session-sync` 把员工的对话上传到当前 [Hub 登录](../../credentials/hub-account/README.zh.md)所在的用户中心，供员工的其他电脑读取。每个顶层会话连同它的子智能体会话作为一个对话包，在它的每一轮结束后上传；登录后的第一次扫描会上传本机已有的会话。附件按内容摘要只上传一次。它也会拉取员工其他电脑上传的对话，在本机保留为只读副本。任何一台电脑上的删除都会同步到其他电脑。失败的请求会重试，离线时记下的删除在重启后照样发出。

<a id="use-this-package"></a>
## 使用本包

把本包作为 Loader 条目挂在 Hub 登录和会话存储旁边；它注入 `hubAccount`、`sessionQuery` 和 `sessionPersistence`，并用 `ctx.get` 读取 `attachments`。web-app bundle 在配置了用户中心的 Desktop 上启用它。只要登录了某个公司的员工就在后台工作，未登录时停止。它的 `sessionSync` Remote 列出拉取来的对话：`getState()` 返回 `{ signedIn, pulled }`，每一项给出拉取来的顶层会话和它来自的电脑；`watch(signal)` 以流的形式推送这个状态；`refresh()` 立即拉取并扫描，Desktop 客户端在窗口回到前台时调用它。

| 字段 | 默认值 | 含义 |
|---|---|---|
| `requestTimeoutMs` | `300000` | 每个用户中心请求的期限 |
| `dshHome` | `$DSH_HOME` 或 `~/.dsh` | 存放同步记录 `session-sync.json` |
| `deviceName` | 去掉 `.local` 的主机名 | 其他电脑上显示的本机名称 |
| `debounceMs` | `2000` | 一轮结束后的等待时间，连续几轮只上传一次 |
| `scanIntervalMs` | `300000` | 扫描间隔，扫描会上传没有结束一轮却发生了变化的会话，例如改名 |
| `retryMs` | `60000` | 连不上用户中心后重试前的等待时间 |

### 一次上传包含什么

顶层会话指不是子智能体会话的已存储会话；分叉出来的会话本身就是顶层会话。它的对话包是 gzip 压缩的 JSON `{ format: 1, sessions }`：先是该会话的完整日志，再是它下面所有子智能体会话的日志，按 id 排序，每份都带会话头和继承事件数。日志里没有用户消息的会话不上传。其中任何一份日志读不出来时，整个对话包等到能读时再传。对话绑定了智能体时，对话包还会写明这些智能体（`assistants`：id、名称和模板），因为每台电脑上的智能体各有各的 id。上传时附带版本号、工作文件夹（超过 1000 个字符时为 null）、电脑名、最新标题（截到 200 个字符）、绑定的智能体 id、附件，以及最新事件的时间。

附件按事件中任意位置的 `sha256:<hex>` id 找出。服务先询问用户中心缺哪些，再通过会校验字节的附件存储读出并上传，只列出用户中心已有的附件。超过 100 MB、排在前 1000 个之后、本机已读不出、或被用户中心拒收的附件不列入，但对话包里仍然引用它。

### 什么时候上传

一轮结束 `debounceMs` 之后、登录和每次登录账号变化时、每隔 `scanIntervalMs`，以及删除之后，各运行一次同步。每次同步先发出当前登录账号待发的删除。扫描再从新到旧查看每个顶层会话；只有日志字节数（后端不提供字节数时用它的版本标记）自上次读取后变化了才重新读取，只有对话包内容摘要变了才上传。因为没有用户消息或读不出而没上传的会话，变化之前不再读取。刚结束一轮的会话总会被读取和比较。对话包在事件循环之外压缩。版本号从 1 开始，每次被接受的上传加一。

记录文件 `<dshHome>/session-sync.json` 为每个顶层会话保存同步所属账号、上次的版本号、内容摘要、存储变化标记，以及对话包被扣下的原因。改动只有写入成功后才算数；记录缺失、读不出或损坏时按空处理，所有会话都会重新读取和比较。

### 用户中心的回应

| 回应 | 结果 |
|---|---|
| 接受 | 记下版本号和摘要 |
| `409 stale_revision` | 用用户中心的版本号加一重新上传；上传三次后这个会话留到下一次同步，其他会话照常进行 |
| `409 missing_attachments` | 重新检查并上传附件，然后重新上传 |
| `410` | 会话已在其他电脑上删除，不再上传 |
| `400` 或 `413` | 对话包被扣下，内容变化后再传 |
| `403` | 该登录不能同步（不是公司成员），在登录变化前不再同步 |
| 其他回应、没有回应或登录已变化 | 本次同步停止，`retryMs` 后再运行 |

### 从其他电脑拉取

登录时、每隔 `scanIntervalMs` 以及调用 `refresh()` 时，同步会拉取一次。它列出该账号自上次拉取以来在用户中心的变化，并为每个账号记下拉取到哪里。本机上传的对话、以及本机已有但不是拉取来的对话，都不会被拉取。其他电脑新建或改动的对话会连同本机缺少的附件一起下载；附件按摘要存进附件存储，图片通过 `saveStoredImage` 原样保存。它选择的智能体会对应到本机同模板（没有同模板时同名）的唯一智能体上，这样对话会显示在该智能体的分组里；对应不上的保留原 id，显示在未知智能体下。其余日志原样写进本机的会话存储，所以侧栏、历史、图片和搜索都像读其他会话一样读它。新版本能接上本机副本时追加在后面，接不上时整体替换。本机正打开的副本先不动；记录里留下要取的版本，之后的同步再补上。读不出或存不进的对话会记日志后跳过，既不耽误其他对话也不耽误上传，它等待中的版本也会作废，直到列出更新的版本。因为用户中心从备份恢复而从头开始的列表，还会删掉列表里已经没有的副本。下载过程中被用户在本机删除的对话保持删除。

拉取来的对话在本机只读，包括它的子智能体会话。发送消息会以 `session-sync/view-only` 被拒（通过 `api-session/prompt-admission`）；它对 `api-session/view-only` 返回 true，所以打开它不会启动 Agent，需要 Agent 的命令（例如重命名）也会被拒。它不会被再上传回去。登录切换到另一个账号时，或者退出登录期间，为原账号拉取的副本会被删掉；再登录回原账号时会重新拉取。状态里的 `changes` 计数在同步每次写入或删除本机日志时增加，提示客户端重新加载会话列表；每个拉取项都带有它的 `revision`。

### 账号与删除

账号指一次登录的公司和手机号，对应一位员工。每个会话归属它第一次上传时的账号；登录其他账号时（其他公司，或同一公司的其他员工）不碰它。删除一个同步过的会话会为它的账号记一条待发删除，该账号登录时发出。读取或上传过程中被删除的会话不记录条目，随后发出删除。在本机删除拉取来的副本，会在用户中心删除这个对话，进而在它的原电脑上删除。其他电脑上删除的对话，下一次拉取时在本机删除：无论是拉取来的副本，还是本机自己的对话，先删子智能体会话。只要其中有一部分正打开，整个对话都等到之后的同步再删。删除从未同步过的会话不发出任何请求。删除子智能体会话也不发请求；下一次扫描会重新上传它的顶层会话。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- **拉取来的副本和本机对话放在同一个会话存储里** —— 只在记录里做标记，没有分开存放；记录丢失时它们看起来像本机自己的对话，会按原 id 再上传一次。
- **打开着的对话会滞后** —— 拉取来的副本或在别处删除的对话在本机打开时，它的更新或删除要等关闭后的同步才进行。
- **暂不支持接着聊** —— 拉取来的对话在本机可以查看或分叉；把它作为新对话继续是后续功能。
- **记不下来的删除会丢失** —— 删除时记录文件写不进去，会话会留在用户中心。
- **请求途中切换登录** —— 每个请求发出前都核对账号；切换登录时已经发出的请求，按发出时的登录完成。

# 推送模板

## 推送规则（双链路独立，服务商整体优先）

**内部群（日报）与服务商群（提醒）为两条独立链路**：内部日报每天生成并发送内部群，不依赖、不携带服务商群的推送执行；服务商群提醒独立判定、独立确认、独立推送。下表只约束服务商群链路：

是否推送外部服务商群，只看服务商整体有效 ROI（账户策略表已停用，全部子表记录参与判定）：

| 服务商整体有效 ROI | 外部群推送 | 内部日报 |
|-|-|-|
| 未达标（< 预警线），且存在低 ROI 账户 | 推送「正常提醒」 | 列入「③ 低 ROI 账户明细」（标注整体状态） |
| 达标（≥ 预警线），即使存在低 ROI 账户 | **不推送** | 列入「③ 低 ROI 账户明细」（标注整体达标） |
| 无数据（消耗合计为 0 / 数据缺失），但存在低 ROI 账户 | 推送「正常提醒」，整体状态标「无数据」 | 列入「③ 低 ROI 账户明细」（标注整体状态） |
| 无低 ROI 账户 | 不推送（静默） | 「② 服务商整体状态一览」中标注「静默」 |

（表中「未达标 / 达标 / 无数据」均按统计窗口内的汇总有效 ROI 判定，窗口按断点续算，正常每天运行为 T-1 单日。）

## 外部服务商群推送（webhook，正常提醒）

按服务商分组、独立消息推送，每个服务商只能看到自己的数据。整体状态二选一（按统计窗口）：

- 外部提醒链路统计窗口由断点决定（1 天或多天），状态标注不再区分单日/三天，统一：
  - 【整体有效ROI未达标】整体有效 ROI < 预警线
  - 【整体有效ROI无数据】统计范围内消耗合计为 0 或数据缺失
- 内部日报链路窗口同样按断点续算，正常每天运行为 T-1 单日；非单日窗口需在日报注明
- （整体达标的服务商不推送，无对应模板）

### 模板

```
【投流ROI提醒｜<服务商名>】
统计范围：<起始日期> ~ <截止日期>（共 N 天）
【整体有效ROI<未达标/无数据>】整体有效 ROI：<值>（预警线：<预警线>）
低 ROI 账户明细：
- 账户名称：<名称>｜账户id：<id>｜投放平台：<平台>
  统计范围内消耗合计：<金额>｜有效GMV合计：<金额>｜汇总有效ROI：<值>
（多个账户逐条列出）
提醒负责人：<at user_id="<负责人open_id>"></at>（open_id 缺失但有姓名明文时改为：提醒负责人：<姓名> <at user_id="all">所有人</at>；姓名也缺则省略整行）
```

### 规则

- 服务商整体达标 → 不推送（即使名下有低 ROI 账户）。
- 无低 ROI 账户 → 静默不推送。
- webhook URL 缺失 → 不推送，列入内部日报「未推送原因」。
- webhook 地址与签名密钥：按 SKILL.md「webhook 与密钥」取，密钥不写进会话回复和预览。
- 自营账户 → 不推送外部群，纳入内部日报。
- **提醒负责人 @**：文案末尾追加「提醒负责人：」行，按配置文档「二、服务商群 webhook 映射」的两列取该服务商负责人：① 「提醒负责人 open_id」列取 `<at user_id="ou_xxx"></at>`（多个空格分隔）；② 「提醒负责人」列取姓名明文；负责人需在该服务商群内，@ 才有提醒效果。
- **负责人解析与群成员核对**：需要解析负责人 open_id 或核对群成员时，用配置文档「外部群 chat_id」列的群 ID 拉成员列表（`lark-cli im chat.members get --as bot`，只读，机器人须在该群内），不要依赖通讯录搜索；该列同时用于群定位与维护。open_id 只对读出它的飞书应用有效：配置文档里的 open_id 须是在 MO 飞书连接下查到的值，@ 不到人时按「负责人兜底」处理并在待处理项列明。
- **负责人兜底**：「提醒负责人 open_id」列为空或「—」，但「提醒负责人」列有姓名明文 → 文案写「提醒负责人：<姓名>」明文，并在其后追加 `<at user_id="all">所有人</at>` 兜底（确保群里有人被提醒）；两列都缺 → 省略该行，不猜测、不 @ 错人，并在内部日报「待处理项」列明该服务商缺负责人配置。


## 内部日报（每天一次，即使全部正常）

发送到配置文档「内部日报接收」指定的内部群（机器人身份发送），**每天一次、即使全部正常，与服务商群是否推送无关**；**发送前必须先以只读预览交付用户，经确认后才发送，定时运行也不例外**。以**互动卡片**形式发送，版式固定为 2026-10-12 用户确认的格式（见下），结论先行（KPI 区置顶）；达标服务商的低 ROI 账户只在「③ 低 ROI 账户明细」面板列示（组标题标注整体达标），不推送服务商群。日报统计窗口按断点续算（正常每天运行为 T-1 单天数据）；补跑覆盖多天时在副标题注明窗口区间与天数。

日报「④ 数据完整性与推送状态」面板的「推送与静默」块按两条链路分别如实标注：内部群日报（本条，已发送）；服务商群提醒（待推送 / 已推送 / 静默 / 未推送及原因），不以一条链路的状态冒充另一条。

### 模板（互动卡片，固定版式，2026-10-12 用户确认「以后都按此格式」）

卡片自上而下共五个部分，结构、字段与排列位置固定：

**卡片标题**
- 标题：`站外投流 ROI 巡检日报`
- 副标题：`<发布日期> 发布｜统计窗口 <起始日> ~ <截止日>（N天·断点续算）｜预警线 <当前值>`
  （补跑多天窗口同样写实际区间与天数；单日窗口写「1天」）

**① KPI 区（4 项，数值加粗）**
- 大盘整体ROI：**<全部服务商窗口内有效GMV合计 ÷ 消耗合计>**
- 消耗合计：**<金额>**
- 有效GMV合计：**<金额>**
- 低ROI账户：**<N> 户**

**② 分隔线 + 服务商整体状态一览**
标题行：`**服务商整体状态一览**（<服务商数> 家：达标 <a> ／ 未达标 <b>）`
按整体有效ROI **降序**逐行列出全部服务商：
- **<服务商>**：整体有效ROI <值>　<达标/未达标>｜低ROI <n>户（无低ROI账户时行尾加「（静默）」）

**③ 分隔线 + 折叠面板「▶ 低 ROI 账户明细（<有低ROI账户的服务商数> 家 <总户数> 户）」**
按服务商分组，只列名下有低 ROI 账户的服务商（整体达标的服务商同样列示并标注，体现「仅内部关注」）：
```
**<服务商>**（整体 <值>，<达标/未达标>）｜<n>户
- <账户名称>（id <账户id>，<平台>）：消耗 <金额>｜有效GMV <金额>｜汇总ROI <值>
```
- 账户按汇总ROI 降序；窗口内日期不全的服务商在其组标题追加说明（如「10-08 无记录，按 10-09~10-11 统计」）。

**④ 折叠面板「▶ 数据完整性与推送状态」**，分三小块：
- **数据完整性**：数据缺失（服务商/日期及处理口径）；「消耗为 0 但有效 GMV>0」的行数与处理口径；消耗合计为 0 的账户清单（不列入低 ROI 提醒）
- **推送与静默**：内部日报（本条，已发送至「<群名>」，机器人身份）；服务商群提醒链路（未运行 / 待确认 / 已推送 / 静默 / 未推送原因）——两条链路如实分列，不以一条链路的状态冒充另一条
- **待处理项**：需运营跟进的事项，无则「无」

**⑤ 分隔线 + 口径脚注**
`口径：服务商整体有效 ROI = 统计窗口内有效GMV合计 ÷ 消耗合计；账户低 ROI 判定 = 汇总有效 ROI < <预警线>。预警线与统计窗口均取自配置文档当前值，不写死。`

### 发送身份

- 内部日报以当前智能体自身的飞书身份发送：MO 飞书连接器的 `lark-cli im +messages-send --as bot --chat-id <配置文档「内部日报接收」群> --msg-type interactive --content <卡片 JSON>`，禁止以用户身份发送；发送成功判据：lark-cli 返回成功且带 message_id。

# 投流 ROI 巡检

## Overview

对站外投流账户执行 ROI 巡检：读取飞书站外投流数据 Base → 按链路统计服务商/账户有效 ROI（统计窗口**统一断点续算**：窗口 = 上次统计截止日次日 ~ T-1，正常运行即 T-1 单日）→ 判定低 ROI → 生成内部日报与外部提醒两套内容 → **两条链路发送前都必须先只读预览给用户，经确认后才发送**。

**核心原则：先预览、后发送，绝不擅自发送。** 内部日报与外部提醒在每次运行（含定时自动运行）时都先生成预览交付用户，只有用户明确说「发送内部日报 / 发送外部提醒 / 正式推送」或明确授权后，才发送对应链路；确认只覆盖当轮。定时运行时没有人在场：只把预览留在本次会话，用户回到该会话回复确认后再发送。

## 唯一配置源

配置文档《投流ROI巡检配置》：https://scnntx5zuepg.feishu.cn/docx/DdcJd7xIyoX1FgxTd5dcAOHXnue
每次运行**必须先读取配置文档全部当前值**（巡检参数 / 服务商群 webhook 映射 / 内部日报接收 / 账户状态规则 / 数据源映射），以当前值为准执行，不得使用历史值或内置默认值。读取用 MO 飞书连接器的 `lark-cli docs +fetch`（只读）。

## 执行流程

1. **读配置**：读取配置文档全部章节当前值。
2. **读断点**：读取工作区 `roi-inspection/checkpoint.json` 中本链路的键，确定统计窗口（见 `references/巡检逻辑.md`「日期语义」「断点文件规范」）。首次运行（无断点）窗口 = T-1 单日，预览注明「首次运行：窗口起点请人工核对」；本窗口已发送过则不重复统计、不再发送。
3. **取数**：按配置「数据源映射」读取站外投流数据 Base（token 与各服务商子表 table_id 都以配置文档为准）各服务商子表统计窗口内记录（`lark-cli base +record-list`，只读）。账户策略表已停用，不再读取。
4. **计算**：按 `references/巡检逻辑.md` 汇总服务商整体有效 ROI 与账户汇总有效 ROI（窗口内），判定低 ROI 与是否推送（全部子表记录参与判定，无跳过规则）。
5. **生成文案**：按 `references/推送模板.md` 分别生成两套内容：① 内部日报（内部群，互动卡片）；② 服务商群提醒文案（外部 webhook，独立于日报）。
6. **只读预览交付（两条链路的强制闸门）**：内部日报全文与外部提醒文案都先生成预览（含「只读预览」声明、统计窗口、各链路将发往哪里）交付用户，**未经确认一律不发送**。
7. **发送（仅当用户确认）**：确认只覆盖当轮、按链路分别授权，两条链路独立执行、互不绑定——
   - **内部日报链路**：用户确认后以智能体自身的飞书身份发送到配置文档「内部日报接收」指定群（任务指令另行指定目标时以指令为准）；统计窗口按断点续算（正常为 T-1 单日，补跑时覆盖断点后一天至 T-1）；日报的生成与发送不依赖任何服务商群推送决策。
   - **服务商群提醒链路**：正常每周一、三、五运行（以调度配置为准；用户明确要求时可临时运行）；每个服务商一条独立消息、只见自己的数据，经 `scripts/send_webhook.py` 签名发送（见下节；测试期发到「测试群」时也逐家各发一条，不合并）；文案末尾按配置文档「提醒负责人 open_id」列 @ 该服务商负责人（缺时按「提醒负责人」列姓名明文 + @所有人 兜底，两列都缺则省略该行并在日报待处理项列明；「待补」「—」「无」或空白都算缺，不是姓名）；日报已发送不代表服务商群已推送，反之亦然。
   - 先测试群 → 用户确认 → 正式推送；两条链路每次发送前都各自走「预览 → 确认 → 发送」。
8. **写断点**：按 `references/巡检逻辑.md`「断点文件规范」写入本链路的键；仅预览、未确认都不写。

**确认时先复核**：用户回复确认时，先重新读取断点文件，只发送本会话**最新**一份预览；若断点在预览之后已变化（别的运行已发过同几天）或预览窗口起点早于断点后一天，不发送旧预览，按当前断点重算后重新出预览。断点只能前移，不能改回更早的日期。

## webhook 与密钥

- 签名 webhook 一律从工作区 `roi-inspection/webhook_mapping.json` 读地址与密钥（由管理员放在本机，格式 `{"webhooks": {"<服务商或测试群>": {"url": "…", "secret": "…"}}}`），由脚本自己读取。配置文档「服务商群 webhook 映射」只用来确定服务商名单、负责人和群；配置文档里给出新的地址或密钥时，先更新这个映射文件再发送，不在命令里写密钥。技能包里不带任何 webhook 或密钥。
- 映射文件缺失、格式不对或没有该服务商 → 不推送，把脚本给出的原因列入内部日报「未推送原因」。
- 发送用 bash 运行脚本，Python 用 `load_workspace_dependencies` 返回的自带解释器（没有时用 `python3`），映射文件写**绝对路径**：`<python> <技能目录>/scripts/send_webhook.py --mapping <工作区绝对路径>/roi-inspection/webhook_mapping.json --name <服务商> --file <消息文件>`。
- 密钥不写进命令、会话回复、预览和日报。
- 脚本退出码：0「发送成功」；1「发送失败」或参数/映射文件有误，消息没有送达，可在下次确认后重发；2「结果不确定」，消息可能已送达——记为「已尝试、结果不确定」，不自动重发，请用户到群里核对后再决定。

## 核心逻辑速查

- 统计窗口：**统一断点续算**（2026-09-20 用户拍板）——每条链路各自记录「上次统计截止日」，窗口 = 断点后一天 ~ T-1；正常运行时窗口即 T-1 单日，周一或补跑时覆盖多天。首次运行（无断点）窗口 = T-1 单日，需人工核对窗口起点。窗口以配置文档「数据窗口」当前值为默认基准；用户指令可临时覆盖本次运行。
- 服务商整体有效 ROI = 窗口内有效 GMV 合计 ÷ 窗口内消耗合计；消耗合计为 0 记「无数据」。
- 账户汇总有效 ROI = 该账户窗口内有效 GMV 合计 ÷ 窗口内消耗合计；消耗为 0 或无法计算不列入低 ROI 提醒。
- 账户低 ROI 判定：账户汇总有效 ROI < 当前预警线（配置文档「巡检参数」）。
- 服务商整体：≥ 预警线「达标」；否则「未达标」；无数据标「无数据」。
- **双链路独立（核心规则）**：内部群（日报）与服务商群（提醒）是两条独立链路，判定、确认、执行、幂等均分开，互不触发、互不阻塞、互不作为前提。
- **服务商群提醒判定（服务商整体优先）**：整体未达标（且存在低 ROI 账户）→ 生成提醒、待用户单独确认后推送；**整体达标 → 即使名下有低 ROI 账户也不推送，仅内部日报「③ 低 ROI 账户明细」列示（组标题标注整体达标）**；整体无数据但有低 ROI 账户 → 按正常提醒生成；无低 ROI 账户 → 静默。
- **内部日报链路**：每次运行生成，不随服务商群推送状态变化；日报内如实标注两条链路各自的状态。
- **断点按链路分键**（`internal` / `external`），互不干扰；发送完成后才前移本链路断点。
- **不平均每日 ROI**，优先用有效 GMV 与消耗合计，按服务商和账户分别汇总。
- 账户策略表已停用：不再读取策略表及「状态」列，无「测试中」跳过规则，全部子表记录参与判定。

## 免提醒名单（2026-10-12 用户确认）

- **剧星、旋龟：停止一切低 ROI 提醒**——外部服务商群 webhook 不再推送这两家（无论整体 ROI 是否未达标、是否存在低 ROI 账户）。背景：剧星仅剩几百元消耗完即停；旋龟约半个月消耗期后停投。
- **数据采集照常**：云台采集与 Base 写入不豁免，两家账户数据照常采集写入。
- **内部日报照常生成**：状态一览仍如实计算并展示两家整体状态，但标注「停投过渡期·已免提醒」，不再列入「低 ROI 账户明细」提醒项。
- 名单为交接时的固定配置；配置文档列有免提醒名单时以配置文档为准。新增或移除免提醒服务商须用户明确确认。

## 推送规则

- 仅整体有效 ROI 未达标（或无数据）且有低 ROI 账户的服务商 → 推送该服务商 webhook；整体达标 → 不推送（低 ROI 账户仅入内部日报「③ 低 ROI 账户明细」列示，标注整体达标）；无低 ROI 账户 → 静默不推送；webhook 缺失 → 不推送，列入日报「未推送原因」。**「免提醒名单」内的服务商（剧星、旋龟）一律不推送外部群，优先级高于本条判定。**
- 外部推送为独立消息，每个服务商只能看到自己的数据。
- 自营账户不推送外部群、纳入内部日报。
- 幂等键按链路分开：内部日报 = 统计窗口 + 内部群；服务商群提醒 = 统计窗口（日期区间）+ 服务商，同一窗口不得重复推送。
- 数据缺失 / 字段缺失 / 服务商无法识别 → 不猜测、不发送错误提醒，内部日报列明失败原因。

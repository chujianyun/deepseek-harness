# 计划 ROI 分析

按需对云台三方外投的计划做 ROI 分档，出一张飞书卡片：总览摘要 → 一、高 ROI 计划 → 优先加码 → 二、建议关停 → 三、账户维度。**全程只读；没有用户明确的发送要求只出预览。**

## 执行流程

Python 用 `load_workspace_dependencies` 返回的自带解释器（`<python>`），`<技能目录>` 指本技能目录；文件放在工作区 `plan-roi-analysis/<今天 YYYYMMDD>/`（下文 `<目录>`，先建好）。Windows 上以带引号的路径开头的命令前加 `& `。

1. **定窗口与阈值**：默认窗口为最近 7 天（到昨天为止，Asia/Shanghai），消耗阈值 700 元、高 ROI 线 1.5、达标线 1.2；用户指定时以用户为准，并在报告中说明。
2. **取数**：运行 `dsh-ecommerce accounts`，选店铺为「名流官方旗舰店」的健康品牌云台账号（`platform` 为 `yuntai`）；没有或已过期 → 停止，请用户到 DSH 设置 → 电商账号重新登录。按 yuntai-details 技能的说明取计划明细：
   ```bash
   "<node>" "<yuntai-details 技能目录>/scripts/yuntai-plans.mjs" --account <账号 id> --from <起> --to <止> > <目录>/plans.json
   ```
   目前只取抖音（站外投流的绝大部分）；报告里注明其他媒体未纳入。失败不重试超过 2 次。
3. **分档与卡片**：`<python> <技能目录>/scripts/plan_roi.py --plans <目录>/plans.json --out <目录> [--spend-min 700] [--hi 1.5] [--mid 1.2]`。它写 `classified.json`（三档清单与账户汇总）和 `card.json`（卡片，已自检：card 2.0 结构、标题、各段内容、大小），并打印摘要。退出码 2 → 报告原因，不发送。卡片里的数一律来自脚本输出，不手算、不改；计划名与计划 ID 原样保留。
4. **预览**：把摘要和卡片各段内容在对话里给用户看，说明将发往哪个群。用户没有明确说「发到内部群」（或指定别的群）就到此为止。
5. **发送（仅当用户明确要求）**：目标群读配置文档《投流ROI巡检配置》https://scnntx5zuepg.feishu.cn/docx/DdcJd7xIyoX1FgxTd5dcAOHXnue 「内部日报接收」当前值（`lark-cli docs +fetch`，只读）；用户指定了群时以用户为准。以智能体自身身份单独运行一条命令，`--content` 用 `@` 加卡片文件相对工作区的路径，由 lark-cli 读文件（不把卡片内容写进命令，Windows 的命令行会拆坏其中的引号）：
   ```bash
   lark-cli im +messages-send --as bot --chat-id <chat_id> --msg-type interactive --idempotency-key plan-roi-<起>-<止> --content "@plan-roi-analysis/<今天 YYYYMMDD>/card.json"
   ```
   不用管道、不拼别的命令；禁止以用户身份发送。成功判据：返回成功且带 message_id；失败报告关键错误，不重试超过 2 次。
6. **交付**：窗口与阈值、计划总数与过线条数、三档条数、整体有效 ROI、优先加码与建议关停的计划（带计划 ID）；发送了就附 message_id 与时间。

## 卡片内容（固定结构）

- 标题「站外投流 · N天高ROI计划清单（起–止）」，蓝色。
- 总览摘要：窗口、过线计划条数（与窗口内总条数）、三档条数、整体有效 ROI（窗口内全部计划的有效 GMV ÷ 消耗）。
- 一、高 ROI 计划：# | 计划名 | 计划ID | 账户 | 消耗 | 有效GMV | ROI，按 ROI 从高到低；卡片超大时减少行数并注明未列出的条数。
- 优先加码：高 ROI 计划中消耗最高的 5 条。
- 二、建议关停：ROI 低于达标线、最低的 10 条。
- 三、账户维度：账户 | 高ROI条数 | 消耗合计 | 有效GMV合计（只算过线计划），附头部高效账户与不达标账户各一句。
- 不含「数据与范围」章节。

## 纪律

- 只读：不改云台投放、不写在线表、不改配置文档。
- 不猜测：计划 ID、账户、金额一律取自采集结果；缺数据如实注明，不补造。
- 不建定时任务。

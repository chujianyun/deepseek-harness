# 连续未达标提醒（固化 · 2026-09-07 用户确认）

> ⚠️ 已暂停（2026-09-28 用户指示）：日常巡检不检测、不推送、不复查，除非用户明确要求恢复。
> 完整规则见云文档《AI巡检固化配置》2.9 节。本文件为 skill 执行速查。

## 业务背景

某负责人负责的项目若**连续两天未达标**，需单独生成提醒报告，由**固定跟踪人**跟进、推动改变动作，**两天后自动复查**数据表现。
对应纪要《业务流程与AI落地相关事项讨论 2026-09-06》「黄灯事件处理：黄灯触发后由固定跟踪人对接合作方沟通解决方案」的分级响应机制。

## 触发标准（用户确认）

- 同一指标/项目**连续两个巡检日**达成率均 **<90%**（含明显+严重偏移，与需优先关注线一致）。
- 任一天实际为空（数据待更新）→ 该天不计入连续天数，连续计数中断。
- 辅助项（花费/费用）不参与；反向指标按反向达成率口径判断。
- 拼多多永久排除店铺不参与；量纲异常「无法计算」不参与。

## 检测与触发时机

- **跟随每日巡检自动检测**：每次巡检读取当日与前一巡检日的达成率，识别连续两天 <90% 的指标/店铺，触发提醒报告。
- 周一/补跑多日巡检时，连续计数按巡检日（有数据的日期）顺序判断，跨周连续。
- 独立于常规日报，命中即单独生成报告。

## 推送对象（2026-09-09 更新：推送跟踪群）

| 角色 | 推送方式 |
|---|---|
| 跟踪群（AI巡检｜连续未达标跟踪） | 提醒报告/复查结果直接推送到群，群内 @ 跟踪人+部门负责人 |
| 固定跟踪人 | 群内 @ |
| 各部门负责人 | 群内 @ |
| 老板（决策者） | 待用户指定具体人；拉入跟踪群即可同步收到 |

- 跟踪群 chat_id、跟踪人与各部门负责人是谁及其 open_id 以配置文档《AI巡检固化配置》2.9 节为准，且必须是 MO 飞书连接下查到的值（open_id 随飞书应用不同而不同，不沿用旧值）。
- 推送身份：当前智能体自身（MO 飞书连接器的 lark-cli，`--as bot`），不使用独立 app 机器人直连脚本。
- 发送成功判据：lark-cli 返回成功且带 message_id。

## 提醒报告模板

```text
【连续未达标提醒｜<平台正式标题名称>】

触发说明：<指标/店铺> 连续 <N> 天达成率低于 90%（<日期1> <达成率1>% → <日期2> <达成率2>%）

涉及负责人：<负责人>
跟踪人：<固定跟踪人>

指标明细：
- <指标/店铺>：目标 X，实际 Y，达成率 Z%（逐日列出）

数据说明：只描述事实，不作绩效结论，不写推测原因。

动作要求：
1. 请跟踪人对接负责人，明确问题解决方案与落地路径；
2. 两天后自动复查该指标数据表现，复查结果单独回报。

说明：本提醒用于部门目标巡检，不做个人绩效打分。
```

## 两天后复查机制

- 触发提醒后登记复查时间 = 提醒日 + 2 天（巡检日口径）。
- 复查内容：读取该指标/店铺复查当日达成率，对比触发时点，输出「已恢复 / 仍低于 90% / 数据待更新」结论。
- 复查结果单独回报给跟踪人与老板；仍低于 90% 则继续跟踪，直到恢复达标或用户叫停。
- 复查同样默认只读，推送需明确指令或已配置自动复查任务。

## 状态登记（建议）

每次触发提醒/复查后，把以下信息记录在本次回复里，便于下一次复查查找：
- 触发日期、平台、指标/店铺、负责人、跟踪人、连续天数、达成率明细
- 复查日期、复查结果、是否继续跟踪

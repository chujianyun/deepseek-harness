# 巡检逻辑（固定 · 不随月份变）

## 日期与周期

- 日报：天猫一店 / 拼多多检查**前一日**。
- 周报：周一生成上一完整自然周周报。
- 无前一日可比数据时写「暂无环比数据」。

## 达成率计算

- 常规达成率 = `实际 / 目标 × 100%`。
- 反向指标（天猫费比、排名等**越低越好**）= `目标 / 实际 × 100%`，报告中注明方向。
- 辅助指标（含「花费」「费用」）= 投放辅助项：**不计入偏移统计与偏移分桶**（不参与「低于90%」计数，不进需优先关注与轻微偏移观察），仅在整体建议中标注辅助项身份（2026-10-10 用户确认）。
- 拼多多目标表单位**万元**；实际多维表单位**元**，读取后 ÷10000 换算万元。

## 偏移分级（默认）

| 达成率 | 等级 |
|---|---|
| >=100% | 正常 / 达标 |
| 90% ～ <100% | 轻微偏移 |
| 70% ～ <90% | 明显偏移 |
| <70% | 严重偏移 |

## 空值与异常处理

- 实际为空 → 「数据待更新」，**绝不按 0 计算**。
- 实际已填数字 0 → 按真实 0 计（达成率 0%），不视为空。
- 目标为空或 0 → 不输出确定性达成结论，标「目标为空，不判断」。
- 量纲异常（实际列存了完成率而非实际量）→ 标「无法计算」，不纳入达标统计。
- 未达计算条件只能标「数据待更新」或「无法计算」。

## 数据完整性检查项

- 目标为空/0、实际为空、日期/目标/实际列定位、排除项、合计行/重复记录、权限或读取异常。
- 输出格式：「当天有 X 个指标尚未填写实际完成」+「本次提醒完整性：完整/不完整」。

## 排除与范围

- 永久排除：`名流器械保健旗舰店`（拼多多）。
- 天猫一店：全部同时具备「指标 + 负责人」的行。
- 拼多多：目标表内配置店铺（不含排除项）。

## 只读与闸门

- 默认只读：不推送、不写回、不修改在线表、不发布。读取只用只读命令（`docs +fetch`、`sheets +cells-get`、`base +record-list`）。
- 只有用户明确「正式推送 / 发送到部门群」，或定时任务指令要求自动推送时，才允许发送；定时任务按指令发到指令列出的目标，不等待确认。
- 发送前核对平台、日期、文案、目标群。
- 对话中推送：先测试群 → 用户确认 → 再正式群。
- 发送成功判据：lark-cli 返回成功且带 message_id。
- 失败保留预览，不报告成功。

## 周报口径（跨日聚合）

- 普通数值（成交 / GMV / 数量）逐日求和。
- 率 / 占比 / ROI / 客单价等非累加指标取周期均值。
- 任一天未填实际 → 该指标标记「数据待更新」。
- 拼多多周报/补跑多日：保留累计达成率 + 最新单日达成率双口径。

## 平台数据源（当前月 token 以云文档《AI巡检固化配置》第五节为准）

| 平台 | 目标来源 | 实际来源 |
|---|---|---|
| 天猫一店 | 当月目标拆解表·店铺整体分表（映射见配置文档第五节 5.1） | 同日期块实际列 |
| 拼多多 | 当月每日店铺任务分解（万元，见配置文档第五节 5.2） | 飞书多维表日数据（元，见配置文档第五节 5.2） |

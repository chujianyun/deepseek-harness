# 推送文案模板（固定 · 精简版统一框架）

> 所有部门巡检日报统一按以下章节生成（2026-09-15 用户确认精简版，替换原十章节）。
> 只保留：日期 / 整体建议 / 需优先关注 / 轻微偏移观察 / 结尾说明（标题保留作平台标识）。
> 平台差异只体现在「整体建议 / 需优先关注」两节的具体口径；标题、章节名、结尾声明全平台一致。

```text
一、标题
【部门群巡检提醒｜<平台正式标题名称>】
（天猫一店→天猫一店；拼多多→拼多多；TTS→北美TTS。不写「市场中心-推广部」。）

二、巡检日期
X月X日（只写日期，不写「检查前一日数据」等说明）

三、整体建议
- 有<90% → 「本日 N 项指标/店铺达成率低于 90%，建议相关负责人复查货品/投放/流量/转化链路。」（N 为实际数量，按平台链路措辞）；
- 有待更新 → 「N 项指标实际待更新（<指标名列表>），建议补齐后复核。」；
- 辅助项说明（如适用）：「花费/费用类为投放辅助项，不计入偏移统计与达成率判断，仅作参考。」；
- 固定表达：「AI只做数据解读和提醒，不替代负责人判断。」

四、需优先关注（达成率<90%、已有目标、实际非空、非辅助项、按平台特殊口径）
按负责人分组，每位：
【负责人】
- <指标>：目标 X，实际 Y，达成率 Z%，暂无环比数据。建议：<核实方向；有原因字段只引用原文>
（有原因/策略字段时在明细行内引用原文，如「原因：…；策略：…」）

五、轻微偏移观察（>=90% 且 <100%、实际非空）
按负责人分组，每组只列「指标：达成率%」，不带目标/实际明细：
【负责人】
- <指标>：<达成率>%
（无命中写「本日无…落在 90%–100% 区间」）

六、结尾说明
请相关负责人回到对应表格补充原因判断、解决动作、预计完成时间。
说明：本提醒用于部门目标巡检，不做个人绩效打分；机器人只发送提醒，不接收回复。
```

## 计算与口径（沿用巡检逻辑，不因精简而改变）

- 常规 = 实际/目标×100%；反向（费比/排名越低越好）= 目标/实际×100%；花费/费用=辅助项：不计入偏移统计与分桶，仅在整体建议标注辅助项身份（2026-10-10 用户确认）。
- 空实际 = 「数据待更新」，绝不按 0；目标空/0 不判断。
- 偏移分级：>=100% 正常；90%~<100% 轻微偏移；70%~<90% 明显偏移；<70% 严重偏移。

## 卡片（原巡检卡片格式，2026-10-16 用户选定）

`scripts/inspection_card.py` 按上面的分级与模板生成互动卡片：蓝色标题「【部门群巡检提醒｜平台】」、副标题「巡检日期：X月X日」，正文依次是巡检日期、整体建议、需优先关注、轻微偏移观察、结尾说明五节（标题在卡片标题栏），节间分隔线；负责人加粗单列一行。达成率天猫一店保留 2 位小数、拼多多 1 位。

输入 `items` 每一行：`owner` 负责人、`name` 指标或店铺、`target` / `actual`（报告单位，拼多多已换算万元；实际为空写 null）、`direction`（`normal` / `reverse` 反向 / `auxiliary` 花费类辅助项）、可选 `note`（原因/策略原文，如「原因：…；策略：…」）与 `suggestion`（建议的核实方向）。分级、计数和整体建议都由脚本算，不手写。

## 预览交付形态

- 用户要求「生成/预览/看一下」→ 在回复中交付脚本打印的预览，结尾加「本次仅生成预览，不推送、不修改任何数据」。
- 推送时发送 `card.json` 原样，不加额外说明，不用富文本。

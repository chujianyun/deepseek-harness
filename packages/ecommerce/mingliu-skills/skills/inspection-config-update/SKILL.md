# 巡检月度配置更新

## Overview

换月时把新月度的天猫 / 拼多多目标表配置进云文档《AI巡检固化配置》第五节，使 ai-inspection 巡检能按新映射运行。**本 skill 只改配置，不跑巡检、不写业务表。**

**核心原则：只改第五节；解析出的每个映射要素必须有出处（表格实际内容或用户确认），缺失不猜、缺啥问啥；改完必须回读核验 + 实测一条数据。**

## 执行流程

1. **收料**：确认月份（如「11月」）与平台（天猫一店 / 拼多多，可能只更其一）。收齐用户给的新目标表：xlsx 文件（用户放在工作区或附件里的文件）或飞书表格链接（记录 token + sheet 名）。材料不全时列出缺什么，向用户要，不用旧表顶替。
2. **读当前配置**：用 lark-cli docs 局部读取云文档《AI巡检固化配置》（https://scnntx5zuepg.feishu.cn/docx/E3cXdNjFQoPknUx34NscD0lAnZb）第五节，掌握当月映射的完整要素清单（见 `references/映射要素与更新规范.md`）。旧映射不要覆盖式遗忘——结构没变的部分（如店铺清单、指标行数）沿用并标注「沿用上月」。
3. **解析新表格**：xlsx 用自带 Python 的 pandas/openpyxl 读（用 `load_workspace_dependencies` 返回的 Python）；飞书在线表用 `lark-cli sheets +csv-get` 读。逐项提取映射要素：目标表 token/sheet、指标行范围与行数、日期块起始列与每日列数（目标/实际/完成率/原因 等列序）、列号公式（如「N 日目标列 = 3+4N」）、单位与量纲、拼多多另需实际多维表 token + table_id + 店铺清单（含永久排除项）。表格结构发生大改时（行列增减、指标变更、负责人变更）逐项与上月对照并向用户确认差异，不静默采纳。
4. **起草新映射**：按配置文档第五节现有格式起草新月份文本（天猫 5.1 / 拼多多 5.2 分块，要素齐全、含「实测核验：待做」标记）。起草结果先在回复中给用户预览确认（涉及结构变化时必须确认；纯换月且结构不变可跳过预览直接核验交付）。
5. **更新云文档**：先读 `lark-cli skills read lark-doc references/lark-doc-update.md` 确认当前写法，再用 `lark-cli docs +update` 局部指令（str_replace / block 替换）只替换第五节中对应平台的小节，**不碰第一至四节**。更新后看 `data.result`（success / partial_success / failed）与 `data.warnings` 判成败，不看外层 ok。
6. **回读核验**：--scope outline 确认章节结构完整，--scope keyword 核对新 token / 列公式 / 排除项等关键值已落到文档。
7. **实测一条数据**：按新映射读一个日期（如当月 1 日）的真实目标值，与原表格核对一致才算配置成功；不一致则回到第 3 步查解析。
8. **交付**：在回复中给出新映射摘要 + 实测核验值 + 云文档链接。提醒用户：旧月份映射可留在文档中作历史记录或归档（按用户意见处理）。

## 边界

- 只更新配置文档第五节；不改巡检逻辑、不改定时任务、不写任何业务在线表。
- 拼多多「名流器械保健旗舰店」为永久排除项，任何新月映射必须保留该排除。
- 配置更新完成不等于巡检已切换——首次巡检前建议用 ai-inspection 做一次只读预览验证。
- TTS 已移出巡检范围（2026-10-10），本 skill 不处理 TTS 映射。

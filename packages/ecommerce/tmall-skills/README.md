# Tmall data skills

English | [中文](README.zh.md)

## Summary

`@deepseek-ai/dsh-tmall-skills` holds nine Skills, not shipped with DSH, that a tenant's admin uploads to the [Skill Hub](../../../docs/glossary.md#skill-hub). With a Tmall [merchant account](../../../docs/glossary.md#merchant-account), `tmall-alimama-scene-report` reads Alimama (万相台) scenes, `tmall-sycm-core-daily` exports Business Advisor's (生意参谋) core daily report, and `tmall-publish-category` finds a new item's category and its form fields. With a [buyer account](../../../docs/glossary.md#buyer-account), `tmall-item-report` reports an item. `ecommerce-product-draft` drafts a product from a material folder; three publish skills save it to a Tmall warehouse or a Pinduoduo or Douyin shop 草稿箱, never on sale; `ecommerce-multi-publish` runs one folder through several stores. Why skills call page APIs is in the [e-commerce accounts Agent Note](../../../.agents/notes/proposed/feature/2026-10-07-ecommerce-accounts-over-store-session.md).

## Use this package

`packSkills(outDir)` builds every skill in `SKILLS` into `<outDir>/<name>/` — its `SKILL.md` from `skills/<name>/` and one self-contained ES module per script under `scripts/`, bundled with tsdown from `src/` — and zips each folder as `<outDir>/<name>.zip` around `<name>/`, the layout Skill Hub accepts; earlier builds are replaced. From the repository root:

```sh
node --input-type=module -e "import { packSkills } from './packages/ecommerce/tmall-skills/src/index.ts'; console.log(await packSkills('dist/tmall-skills'))"
```

The two merchant scripts take `--account <id>` (an id from `dsh-ecommerce accounts`), `--date YYYY-MM-DD` (a day that has ended in Beijing time, yesterday by default), and `--out <dir>` (`天猫报表` under the working directory by default). It runs `dsh-ecommerce browser <id>`, which DSH answers only inside a bash call while a tenant is signed in; refuses an account that is not a Tmall merchant account; opens a background tab in the account's Chrome and closes it afterwards; and prints a Markdown summary with the paths of the files it wrote. It exits `0` on success, `2` when the platform has not finished the day (nothing written), `3` when the account is signed out of the platform, `64` for a wrong command line, and `1` otherwise, with the reason on stderr.

- `scripts/alimama-scene-report.mjs` opens Alimama's account report page for the day, captures the scene query the page sends (its `csrfId` and `loginPointId` are made at run time), and posts it again with the fields it reads. A page sent to the sign-in screen that offers 「进入后台」 is entered once. For yesterday (Beijing time), no scene or zero de-duplicated buyers in every scene (`alipayInshopUv`, computed after about 10:00 the next morning) stops it as not ready; earlier days are reported as they are. Otherwise it writes `万相台营销场景报表_<store>_<date>.csv`, one row per scene with spend, impressions, clicks, transactions, carts, and natural traffic, rates recomputed from the unrounded figures, and a `.md` summary with totals; when every scene reads zero natural impressions, which Alimama computes later than the other figures, the summary warns that the two natural-traffic columns are not computed yet.
- `scripts/sycm-core-daily.mjs` calls the self-service data APIs: the template list for 「店铺经营核心日报」, the export request, and the download address, which it polls for up to two minutes, then downloads the .xlsx (the last 30 days) from that signed address. A file without the day, or a Business Advisor update day (`commDateByLocation`) before it, is not ready, and the message names the days the file covers and the update day; a day older than the file's first day is a usage error. A failure while asking Alimama leaves the report unverified rather than failing it. It then compares the 关键词推广, 精准人群推广, and 全站推广 spend with Alimama's scenes 371, 372, and 436 in the same tab, allowing one cent. It writes `生意参谋店铺经营核心日报_<store>_<date>.csv` (every column of the day), the export as `.xlsx`, and a `.md` summary whose check line under the title is ✅ matching, ❌ with each difference, or ⚠️ with why Alimama could not be asked. A spend cell that is not a number counts as no spend.

`scripts/publish-category.mjs` (skill `tmall-publish-category`) takes a command, `--account <id>`, and `--out <dir>` (`天猫发品`), and takes over the merchant account the same way. `categories` walks the category tree of Tmall's publish entry (`sell.publish.tmall.com/tmall/ai/category.htm`, endpoint `categorySelectChildren&fromSmart=true`) down to the categories marked publishable, keeps those the store is authorized for, and caches them as `类目缓存_<store>.json` for 7 days (`--refresh` reads again); a cache lacking a category a command looks for is read again, and a walk that finds no category fails instead of being cached. `resolve` takes exactly one source: `--cat <id>` must be one of those categories (exit `64` otherwise); `--item <link or id>` and `--own <title words>` read the store's own items through the Qianniu item manager's signed `mtop.tmall.sell.pc.manage.async` call, the latter grouping matches by category, most items first; `--keyword <product name>` uses the entry's category search (`retrievalDataAsyncOpt`) and names the categories the store is not authorized for; `--line <product line>` takes the category the company remembered for that product line (`dsh-ecommerce memory`), while the store may still publish in it. An item from another store yields no candidate and a note, since its public page names only the top-level category. `rules --cat <id>` checks the category against the store's categories, opens the publish page Tmall's AI publishing opens (`publish.htm?catId=…&newRouter=1&fromAIPublish=true`), and reads the form the page carries (`window.Json2`): every field with its control, required flag, length limit, options, and the page's show/require conditions, category properties (`keyProp`, `bindProp`, `itemProp`) expanded, and required single-option checkboxes, such as 「个人使用确认」 and 「产品确认」, marked as declarations. A sign-in page reached at any point exits `3`. It prints required fields, declarations, and conditionally required fields and saves `字段规则_<id>.json`; a page without the form or with a form of no fields fails with exit `1` and what the page said, and a category Tmall refuses exits `64`, never with an empty rule set. Nothing is published or saved on the platform.

`scripts/product-draft.mjs` (skill `ecommerce-product-draft`) reads local files only and takes a command, `--folder <dir>`, and `--out <dir>` (`发品草稿`). `inventory` lists every file under the folder (hidden ones left out) and saves `素材清点.json`. Images are decoded by their bytes (PNG and JPEG, whatever the extension, which is flagged when it lies) for size, transparent share, and white-border share, and sorted by rules: the file name, then its folders from the nearest out (`sku`/颜色分类 → SKU image, 详情 → detail, 白底/纯白 → white, 透明/抠图 → transparent, 场景 → other, 主图/方图 → main split by shape into 1:1 and 3:4), then pixels and shape alone (transparent, square with a white border, square, 3:4, taller than 1.3), where several unnamed white-border squares count as main images; anything else is 待判断 for the model. Each worksheet of an .xlsx file and each .csv file gets its header row (the first with two filled cells) and each column the SKU field its name suggests (index, name, code, count, price, stock, or unit price). `draft` takes `--answers <json>`, the model's column fields, image kinds, SKU images, and values with their sources (素材原值, 店铺资料, 沿用旧商品, 模型生成), and `--rules <json>`, a field-rules file of `tmall-publish-category`. It reads the SKUs from the table with the most fields that has a name and a price, checks prices, whole numbers, duplicates, and price ÷ count against a unit-price column, gives each SKU one image of its own by the model's answer or by the first number in the file name matching the number in its index (its table row without an index column), and lists the 商品标题, 商品卖点, and 导购标题 the model still has to write. With rules it checks every required field: images by kind (at most 5 main and 3:4 images), declarations as 待店铺确认, 上架时间 as 放入仓库, 一口价 as the lowest SKU price or a given one that must equal a SKU price, 商品数量 from the SKU stock, and other fields from values by label, options compared with full-width forms folded, spaces dropped, and 其它 read as 其他; a closed option outside the list or a text wider than the field's length limit (a Chinese character counts 2) is 不符合, a model-written value, the price included, is 待确认, and each check saves the values to submit with options as the platform writes them. A missing material is listed as missing; no other image fills it. With `--store <store>`, it reads the company's publishing memory through `dsh-ecommerce memory`: the store's remembered values fill the values the answers leave out (source 店铺资料) — with rules, only for fields the category's form shows — remembered table headers set the columns the answers do not, and a declaration the store confirmed for the category with the same text is 已确认 with its time in Beijing time, while one whose text changed is asked again; the checklist's notes say what came from the memory. With `--plan <发品计划 json>` (from `ecommerce-multi-publish`), a title, selling point, or guide title the user confirmed on an earlier store's card, when this store's form has it, fills the answers when they leave it out or repeat it, with source 用户确认 and status 已确认; a value the answers changed stays the model's, and the notes name both. It saves `商品草稿.json` and `待确认清单.md`. It exits `0` with or without missing items, `64` for a wrong command line, folder, answers, or rules file, and `1` otherwise.

`scripts/publish.mjs` (skill `tmall-publish`) takes a command, `--account <id>`, `--draft <商品草稿 json>`, and `--out <dir>` (`天猫发品`), and takes over the merchant account the same way. `check` looks through the Qianniu item manager's `all` tab, on sale and in the warehouse: first for the item ids its record `发品记录.json` holds for the same product in the same store (the same title, or the same SKU codes), then for the draft's title, and says what it found, changing nothing; a draft without a title exits `64`, and more than 20 items carrying the title's words exit `1`, since the manager answers 20 rows. `save` also takes `--rules <json>`, the same field-rules file, `--confirmed`, which the model passes only after the user accepted the draft in the confirmation card, `--stock <n>`, the stock of SKUs the table gives none, and `--unknown-checked`. It refuses (exit `64`, every reason listed) a draft not checked against those rules, with missing materials or problems, a required field missing (fields with show conditions left out), a value 不符合, a declaration not confirmed, a SKU without stock, or, without `--confirmed`, a 待确认 value; it returns the item instead of saving, recorded as `exists`, when `check` would find one; and while the product's last attempt ended `unknown` or stopped while `submitting`, it refuses (exit `64`) until the user found in Qianniu that nothing was saved and `--unknown-checked` is passed. Then it writes a `submitting` record, prints progress lines to stderr, opens the publish page, reads the page's own values (`window.Json2`: the item id it reserved, its trace, each field's default, and the SKU measurement column), and uploads the images to the image space folder 「DSH发品」, made when missing (`mtop.taobao.picturecenter.console.dir.*`, `stream-upload.taobao.com/api/upload.api`); an image whose MD5 the folder already has is reused, the white and transparent images are cut to 800×800 when they are not, and each name carries the file's real format. The form is the page's values with the draft set in: titles, images, category properties, declarations confirmed, delivery time, SKUs with price, stock, code, count, and image under 颜色分类, price, quantity, the SKU codes' common start as the item code, 上架时间 放入仓库, and the detail images as one picture module each. The page's own request helper (`GlobalStore.app.request`, which adds the headers Tmall's gateway requires) posts it to `/tmall/submit.htm`. A failure before the submit, and Tmall's form errors, are recorded as `failed` and printed (exit `1`); a submit that never answered is recorded as `unknown` and says to run `check` rather than retry. An item Tmall reports saved is looked up in the warehouse by id: found, it is `saved` and the script prints its id and the edit and warehouse links; found on sale instead, it is `on-sale` and the script tells the user to take it off sale at once (exit `1`); found nowhere, it is `unknown` (exit `1`). Each call takes at most 60 s for the image space, 120 s per upload, and 180 s for the submit. Nothing goes on sale.

`scripts/pdd-publish.mjs` (skill `pdd-publish`) takes a command, `--account <id>` (a Pinduoduo merchant account), and `--out <dir>` (`拼多多发品`). It works in a signed-in goods-list page of the merchant backend, which starts no edit session on opening: every backend call there must carry the page's risk-control payload (`anti-content`, refused with 54001 without it), so each call takes the page's own anti-content module through the page's webpack runtime and sends the payload it makes. `resolve` takes one source: `--keyword` (the category page's search, `search/categories/v2`), `--line` (the company's remembered category with platform `pinduoduo`), `--cat <id>`, or `--image <file> --title <title>` (Pinduoduo's prediction, `category/predict/list`, which needs an uploaded image and an edit session); categories the store lacks the qualification for are named apart. `children [--parent <id>]` lists one level (`categories?parentId=`). `rules --cat <id>` reads the property template (`draco-ms/mms/template/mall`) and the publish limits (`query/rules/limit/new`) and saves `字段规则_<id>.json` (with `platform: pinduoduo`) in the field-rules format `ecommerce-product-draft` checks: title (the limit's width, 60), carousel and detail images, each property under `p-<ref_pid>` with its options, SKUs and stock, 发货时间 from the ship-within choices, and two prices Pinduoduo needs besides the SKU (group) price: 单买价比拼单价高（元） and 参考价（元）. `check` and `save` take the same options as `publish.mjs` and keep the same record file and rules: the same product is found by an earlier draft id still in the 草稿箱, a draft with the same title (`query/commit/list`), or an item with the same title or an earlier goods id (`query/display/mall/goodsList`). `save` also refuses rules of another platform and prices that do not work: the markup must be above 0 and the reference price above the highest single-buy price. It starts one edit session (`edit/commit/create_new`), puts it in the category (`update_goods_commit_info`), uploads the images (`galerie/business/get_signature`, then `file.pinduoduo.com/v3/store_image`), makes each SKU name a 套餐 spec value (`query/spec/by/name`), and saves the session's own values (the fields its save form carries) with the draft set in through `goodsCommit/action/edit`: up to 10 carousel images and the detail images in `gallery`, properties as `goods_properties` (a 保质期 such as 「5年」 in days), SKUs with group and single-buy prices in fen, stock, code, and image, the reference price, ship-within time, and the SKU codes' common start as the item code. A refusal is `failed`; no answer is `unknown`. The draft is then looked up in the 草稿箱 for up to 30 s. Nothing is submitted for review or put on sale. Pinduoduo refuses edit sessions started too often (「操作过于频繁」), so only `save` and an image `resolve` start one.

`scripts/doudian-publish.mjs` (skill `doudian-publish`) takes the same commands and options as `pdd-publish.mjs` for a Douyin shop merchant account, with `--out <dir>` (`抖店发品`), and keeps the same record file and blockers. Reads are plain calls from a seller page; other calls go through the page's `XMLHttpRequest`, which the page's security SDK signs. `resolve` uses the category search (`searchCategoryN`), the remembered line (platform `doudian`), `--cat` (`getCategoryDetail`), or Douyin shop's prediction from the main image and title (`predictCategoryN`, an asynchronous task whose state the same call answers given its task id); a category with a level the store did not open (`categoryOptionsN?display_all=0`, checked level by level for `--cat` and `--line`) is named apart, and `children` lists only opened categories. `rules --cat <id>` opens the new-item page in the category (`/ffa/g/create?category_leaf_id=`), finds the page's form store in its React tree, and reads the category properties, the qualifications with the store's qualification library, the freight templates, the shipping times, and the reference price's proof kinds from the form; it saves the field rules with the library entries' images (`qualificationImages`), since the entries are named by upload time. Besides the category properties, the rules hold the title (width 120), main and detail images, one field per qualification (`资质：…`, chosen from the library), SKUs and stock, 运费模板, 现货发货时间, and three optional fields: 商品重量（克）, 参考价（元）, and the kind and image file of its proof. `save` refuses a reference price that is below the highest SKU price, reaches ten times it, or lacks its proof. It uploads the images (`/product/img/batchupload`), has Douyin shop render the detail images as 详情装修 image components (`formatPrettifyForProduct`), since the page's draft save empties a detail its 详情装修 does not hold, opens the new-item page in the category, makes the page refuse any submit that is not a draft save (every `…WithSchema` submit, sent by `XMLHttpRequest`, `fetch`, or `sendBeacon`, goes out only with `check_status=1`), sets the values into the page's form store in two passes — the second for the weight and the reference price, which the page opens only after the first — checks the form holds 商品状态 下架, the reference price, and the detail, and runs the page's own draft save, which builds the request and its signature. A freight template that charges by weight and a draft without a weight stop before the save. Refusals and a form not ready are `failed`; no answer is `unknown`. The product is then looked up: listed on sale, it is `on-sale` and the user is told to take it off sale; listed in the 草稿箱 within 30 s, it is `saved`; listed otherwise, it is `not-draft` and the user is told to check it. Before saving, an item already in the store is looked for among DSH's records, the products, and the 草稿箱 titles. Nothing is submitted for review or put on sale.

`scripts/multi-publish.mjs` (skill `ecommerce-multi-publish`) saves nothing to a store; it keeps the plan of one material folder published to several stores in `--plan <file>` (`多店发品/发品计划.json`). `plan --folder <dir> --account <id> …` lists the accounts through `dsh-ecommerce accounts`, takes only Tmall, Pinduoduo, and Douyin shop merchant accounts, each once, and refuses to overwrite a plan without `--replace`. `next` names the first store nothing happened for since the plan began, the skill to use, and per-store directories for its rules (`<platform dir>/<store>`) and draft (`发品草稿/<platform>-<store>`), quoting words bash would split; a store that saved, failed, waits, or was cancelled is never named again, so a failure is not retried. `confirm --account <id> --draft <json>` takes a draft from that store's draft directory, refuses a store already dealt with, records that its card was confirmed, and keeps the draft's 模型生成 商品标题, 商品卖点, and 导购标题 as shared content when no earlier card set them; `product-draft draft --plan` then takes those of them the store's form has, and other values stay with each store's own card. A store's result is the latest of its platform record file's entries for that store since the plan began (by the saving account the publish scripts now record, or by store name for older entries) and of the marks `mark --account <id> --status failed|pending|cancelled --note <text>` adds for a step that writes no record: `saved` and `exists` are 成功; `failed`, `on-sale`, and `not-draft` are 失败; `unknown`, `submitting`, and `pending` are 待确认; nothing or `cancelled` is 未执行. `summary` prints a table of every store with the counts and saves it as `发品汇总.md` next to the plan. It exits `0`, `64` for a wrong command line, an existing plan, an account outside the plan or unable to publish, or an unreadable file, and `1` otherwise.

`scripts/item-report.mjs` takes item links or ids, `--questions` (100), `--reviews` (200), `--appends` (100), `--per-tag` (100), and `--out <dir>` (`天猫报表`). It runs `dsh-ecommerce buyer`, which picks the buyer account that can be used and has opened the fewest pages today, and opens one item page per item (`item.taobao.com/item.htm?id=…`, which DSH counts once however it redirects); before each item it stops when the account's pages left for today are used. On the page it reads the server-rendered data (`__ICE_APP_CONTEXT__`: title, shop, price, main images, video, SKUs with prices, stock, and option images), the description images from the page's own `mtop.taobao.detail.getdesc` response (a replay is refused), then calls through the page's own `lib.mtop.request`, 4.5–6 s apart: 问大家 (`mtop.taobao.wdj.list.merge.search`, 20 a call) and reviews (`mtop.taobao.rate.detaillist.get`, 50 a call) — the main list in the platform's default order, each negative impression tag (label id ending in -13, or gray), and the follow-up tab — each labelled with its source. A slider, a verification, `RGV587`, or a call left unanswered for 20 s stops the whole run at once without retrying, verifying, or switching accounts, and `dsh-ecommerce risk <id>` rests the account in DSH; DSH refusing the page (`ERR_BLOCKED_BY_CLIENT`) stops it too. Another failure of 问大家 or reviews loses only that part, and an item page that is not a standard one or has no SKU data is skipped; both are named, and the run goes on. Whatever was read is written to `单品_<id>/` (`item.json`, `skus.csv`, `questions.csv`, `reviews.csv`, `reviews_negative.csv`, `facts.json`, `报告.md`, and `images/` downloaded with a Tmall referer), and items not reached are named. `facts.json` and `报告.md` hold only counts with their samples and verbatim quotes: the SKU price ladder per piece, purchased-SKU shares from the main list, rating distribution by month, negative reviews (中差评, negative tags, negative follow-ups) by category, positive themes, and 问大家 concerns. It exits `0` when every item was read in full, `4` when risk control or the page limit stopped it, `3` when the buyer account is signed out, `64` for a wrong command line, and `1` when an item was not read in full or anything else failed.

<a id="model-experience"></a>
## Model Experience

Indirectly, through the Skill Hub install and the bash tool; DSH does not load this package. An installed skill's catalog description is the `description` in its `SKILL.md`, in Chinese for the tenant's employees. The merchant skills' bodies tell the model to pick the account by the `ecommerce-accounts` rules, to get the Node path from `load_workspace_dependencies`, to run the script in one bash call relative to the skill's base directory, and what each exit status means: relay the summary and file paths, say the data is not ready rather than make up figures, send the user to Settings when signed out without switching stores, and pass on a spend mismatch with both figures. The item skill's body tells the model to run the script with a 600000 ms bash timeout, since the buyer account is reserved only for that call, to raise limits only when the user asks, to base conclusions on the report's counts and verbatim quotes with their samples, and, after risk control, not to retry, verify, or switch accounts. The publish-category skill's body tells the model to try the category sources in order, to let the user confirm any candidate that did not come from a given id or an own item, and to relay declarations verbatim without accepting them for the user. The product-draft skill's body tells the model to settle 待判断 images by looking at them or asking the user, to write the titles and selling points itself as 模型生成, to write only values the user or the store gave, never registration numbers it guesses, and to ask for missing materials rather than substitute images. The publish skill's body tells the model to list the draft item by item, then ask in a question card whose options are, in order, 修改某项, 重新生成标题, 补缺失, 取消, and 一键认可，保存到仓库, none marked recommended, so the preselected first option never saves; to run `save --confirmed` with a 600000 ms bash timeout only after the user chose 一键认可; to stop on an item already in the store; to pass `--unknown-checked` only after the user said Qianniu has no such item; to have the user confirm a declaration's text the first time and remember it; and to save only through `publish.mjs save`, never by changing, copying, or writing scripts or calling Tmall itself, reporting an error to the user instead of fixing and retrying. The Pinduoduo publish skill's body follows the same card and rules for the 草稿箱, and tells the model to find the category by remembered line, product name, or main image and have the user confirm a guessed one, to write properties with the platform's option text and never invent registration numbers, and to have the user give or confirm the single-buy markup and the reference price. The Douyin shop publish skill's body adds that a qualification is chosen only from the store's library, showing the user the entries' images when it is unclear which, that a missing weight or reference price is asked for in the card, and that a reference price needs its proof image in the material folder. A script prints its summary to stdout (a table of a few rows, or for `rules` about 30 field lines) and one reason line to stderr when it stops.

#### KV Cache effect

No direct effect; installing or removing a skill changes the skill catalog the way any installed skill does.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

- **Data from Tmall and Taobao** — the reports read Tmall merchant and Taobao/Tmall buyer data; for Pinduoduo and Douyin shop there is only the draft save.
- **Only page loads count** — DSH counts the item page; the paced API calls of 问大家 and reviews do not count toward the daily pages.
- **One bash call reserves the buyer account** — a run promoted to the background after the bash timeout loses the reservation and DSH's watch; the defaults keep a run to about 1–2 minutes per item.
- **The warehouse save covers one form** — `tmall-publish` fills the fields the 避孕套 category's form needs: 颜色分类 as the only sale property, the detail as images only, no video; a category with other sale properties or required fields stops with Tmall's form errors.
- **Uploaded images stay** — the images an attempt uploaded stay in 「DSH发品」 when Tmall refuses the form; the next attempt reuses them by MD5, and nothing removes them.
- **Keyword tables follow one category** — negative categories, positive themes, and 问大家 concerns are tuned for the adult-health items the first tenant sells.
- **No full answers or keyword search** — each 问大家 question keeps the top answers its list gives; search pages, price watching, and competitor monitoring are later work.
- **Page APIs follow the platforms** — the report query, its session fields, the self-service template name, and the export APIs belong to Alimama and Business Advisor; when they change, a script stops with the reason until it is updated.
- **Readiness by one signal each** — yesterday's Alimama figures are ready when any scene has buyers, so a yesterday with advertising but no sale reads not ready until the next day.
- **Attribution keeps moving** — Alimama counts transactions for days after the click, so a later run for the same day can show larger transaction figures.
- **Last 30 days of Business Advisor** — the template exports only the last 30 days.
- **The cross-check covers spend only** — visitors, payments, and buyers have no second source here.
- **Sorting by names and shapes** — images without name hints are sorted by shape and pixels; a scene photo without a hint reads as a 1:1 main image, and images in WebP or other formats are left 待判断.
- **Memory is written by the model** — the skills read the publishing memory but never write it; the model saves what the user confirmed with `dsh-ecommerce remember`, as the skill bodies tell it, so an entry the user never confirmed is never remembered. Values of earlier items still come from the user in the conversation, and the draft checks only against Tmall's field rules.
- **Saved, never submitted** — the skills save to a Tmall warehouse or a Pinduoduo 草稿箱 and stop there; the user puts an item on sale. Tmall's conditions stay in the page's own expression syntax, so a field required only under a condition is listed as missing with a note.
- **The 草稿箱 save covers one form** — `pdd-publish` fills 套餐 as the only spec, the detail as images only, and the properties the template lists; Pinduoduo's other services (service promises, video, size charts) keep the session's defaults.
- **The Douyin shop save drives the page's form** — `doudian-publish` finds the new-item page's form store in its React tree and calls the page's own save, so a rebuilt page without that store stops the script; it fills 规格 as the only spec, the detail as images only, and leaves the page's defaults for after-sale, promotion, and other fields.
- **The model drives a multi-store publish** — `ecommerce-multi-publish` keeps the plan and the results but runs no store itself; the model runs each store's skill, one store at a time, as the skill body tells it, and a store left 待确认 is resumed outside `next`. Two stores of one platform share its record file and are told apart by the saving account. A store's result is the latest record for its account since the plan began, whatever product it names.
- **Pinduoduo deletes idle drafts** — the 草稿箱 says a draft nobody edits for 15 days is deleted, so a saved draft must be submitted or edited by then; the record then names a draft the store no longer has.
- **A given category is not checked for qualification** — category detail does not say whether the store holds a category's qualification, so `--cat` and `--line` list it as usable and Pinduoduo refuses it only at the save; search and prediction name the categories the store lacks.
- **The anti-content module is found in the page** — the script takes webpack module `fbeZ`, or else a loaded module whose instances make a `messagePack`; when Pinduoduo rebuilds its pages without either, the script stops until it is updated.
- **Exports leave records** — each Business Advisor run adds an export to the store's self-service download list.

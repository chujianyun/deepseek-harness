# 拼多多发品存草稿

只存草稿箱，绝不提交发布；发布由用户在拼多多商家后台自己确认。

## 步骤

1. 选账号：按 `ecommerce-accounts` 技能的规则选目标拼多多店铺的商家账号；`<店铺名>` 用 `dsh-ecommerce accounts` 里该账号的 `store`。运行 `dsh-ecommerce memory` 看公司记住了什么。调用 `load_workspace_dependencies` 取 `node` 路径；下面的脚本都相对本技能目录，每条命令一次 bash 调用。
2. 定类目：`"<node>" "<本技能目录>/scripts/pdd-publish.mjs" resolve --account <账号 id>` 加一个来源：
   - 记住过产品线就先用 `--line <产品线>`；
   - 否则 `--keyword <商品名>`（拼多多类目搜索），或 `--image <主图文件> --title <标题>`（拼多多按主图和标题推荐）；
   - 用户给了类目 id 就 `--cat <类目 id>`；要逐层看就用 `children [--parent <类目 id>]`。
   除了用户给的类目 id 和记住的产品线，候选类目都要请用户确认；确认后用 `dsh-ecommerce remember` 记下产品线的类目（平台写 `pinduoduo`）。
3. 读字段规则：`... rules --account <账号 id> --cat <类目 id>`，得到 `拼多多发品/字段规则_<类目 id>.json`（含类目属性、发货时间可选值、标题长度上限）。
4. 整理素材：用 `ecommerce-product-draft` 技能（`draft` 加 `--rules <上一步的文件>` 和 `--store <店铺名>`）。答案文件里除了标题，还要写：
   - 类目属性按字段规则里的名字写，选项按规则里的原文写（如品牌「Personage/名流」、医疗器械管理类别「第二类」）；注册证号只写用户或店铺资料给的，不编造；保质期写「5年」这类，脚本换算成天数。
   - `单买价比拼单价高（元）`：SKU 表里的价格是拼单价，单买价 = 拼单价 + 这个数；
   - `参考价（元）`：要高于最高的单买价；
   - `发货时间`：按规则里的选项写（如「48小时」）。
   这些价格由用户或店铺资料给出；你推算的写来源 `模型生成`，在卡片里请用户确认。
5. 确认卡片：先在消息里把草稿逐项列给用户——图片各几张、SKU 表（名称、编码、拼单价、单买价、库存、SKU 图）、参考价、每个类目属性的值和来源、发货时间、还缺什么。然后用提问卡片问「确认保存到 <店铺名> 的拼多多草稿箱吗？」，选项按下面的顺序（卡片默认选中第一项，所以第一项不能是保存）：
   - **修改某项**（用户在卡片里写要改什么，你改答案文件后重跑第 4 步，再回到第 5 步）
   - **重新生成标题**（你重写商品标题后重跑第 4 步，再回到第 5 步）
   - **补缺失**（问用户缺的内容；素材要用户放进文件夹，不拿别的图顶替）
   - **取消**（什么都不保存，告诉用户已取消）
   - **一键认可，保存到草稿箱**
   这张卡片和之后任何会导致保存或重试保存的卡片都**不要给任何选项标「推荐」/(Recommended)**。清单里还有「缺失」「不符合」时先补齐，不要保存。
6. 用户选「一键认可」后保存：`"<node>" "<本技能目录>/scripts/pdd-publish.mjs" save --account <账号 id> --draft <商品草稿.json> --rules <字段规则.json> --confirmed [--stock <每个 SKU 的库存>]`。`--confirmed` 只能在用户这一轮选了「一键认可」之后加。bash 超时设为 600000 毫秒。脚本保存前会先查草稿箱和商品列表有没有同一商品（同标题，或 DSH 存过的同一组 SKU 编码），有就不保存。
7. 回复：草稿 ID、商品 ID、标题和草稿箱位置，提醒用户到拼多多后台草稿箱确认后自己提交发布。

用户只想知道店里有没有这件商品时，运行 `... check --account <账号 id> --draft <商品草稿.json>`，它只查不改。

## 结果与退出码

- `0`：已保存并在草稿箱里查到；或店里已有同一商品，没有重复保存（输出会写明）。
- `64`：还不能保存（列出缺失、不符合、待确认的项），或参数错误。补齐后再走第 5 步。也可能是上次保存结果不明：请用户到拼多多后台草稿箱和商品列表确认没有这件商品；用户明确说没有后，才能在 save 后面加 `--unknown-checked`。
- `3`：账号需要重新登录。
- `1`：拼多多没有保存（列出原因），或保存后结果不明。**不要自动重试**；把原话告诉用户。

## 规则

- 保存只能用本技能的 `pdd-publish.mjs save`。**不要修改、复制或另写脚本，也不要自己调用拼多多的接口去保存或上传**；脚本报错就把原话告诉用户，由用户决定，不要自己「修好再试」。
- 绝不提交发布，只存草稿箱；不改店铺里已有的商品和草稿。
- 用户选「取消」或没有明确认可时，什么都不保存。
- 失败或结果不明时不自动重试，不换店。
- 模型生成的内容在用户认可前不算数。

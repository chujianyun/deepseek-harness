# 生意参谋店铺经营核心日报

导出天猫店铺生意参谋「自助取数 → 店铺经营核心日报」模板（最近 30 天，按天），取出指定日期那一行，并把其中的推广花费与万相台同日数据核对。脚本调用生意参谋页面自己的接口，不改动店铺。

## 步骤

1. 选账号：按 `ecommerce-accounts` 技能的规则运行 `dsh-ecommerce accounts`，从 `platform` 为 `tmall`、`kind` 为 `merchant` 的账号中选一个。只有一个已登录时直接用，并在回复里写明用的是哪家店；有多个时先问用户；没有可用账号时停下，请用户到 DSH 设置 → 电商账号登录。
2. 取 Node：调用 `load_workspace_dependencies`，用它返回的 `node` 路径运行脚本（员工电脑不需要另装 Node 或 Python）。
3. 在用户的工作区里，用一次 bash 调用运行（`scripts/` 相对本技能目录）：

   ```sh
   "<node>" "<本技能目录>/scripts/sycm-core-daily.mjs" --account <账号 id> --date <YYYY-MM-DD>
   ```

   - `--date` 省略时取昨天（北京时间）；只能取已经过去、且在最近 30 天内的日期。
   - `--out <目录>` 指定输出目录，默认是工作区下的 `天猫报表/`。
4. 把脚本打印的摘要转述给用户，并写明文件保存的位置。摘要第一行是交叉校验结果，必须如实转述。

## 结果与退出码

- `0`：成功。保存 `生意参谋店铺经营核心日报_<店铺>_<日期>.csv`（这一天的全部指标，两列：指标、数值）、同名 `.xlsx`（生意参谋导出的原始文件）和 `.md` 摘要。
  - 摘要以 ✅ 开头：推广花费与万相台一致。
  - 以 ❌ 开头：推广花费与万相台不一致。告诉用户哪几个场景对不上、两边各是多少，请他们人工核对；不要只报其中一边的数字当作结论。
  - 以 ⚠️ 开头：没能交叉校验（例如万相台暂时打不开），说明原因，并提醒用户这份数据未经核对。
- `2`：数据未就绪。生意参谋还没有更新到这一天，此时脚本不写任何文件。如实告诉用户稍后再试。
- `3`：账号需要重新登录。请用户到 DSH 设置 → 电商账号重新登录，不要换别的店铺。
- `1` / `64`：其他失败或参数错误（例如店铺没有自助取数权限），把脚本的说明原样告诉用户。

## 规则

- 只读：不要修改店铺、模板或任何设置。
- 一次任务只用一个账号；失败时不要自动换店。

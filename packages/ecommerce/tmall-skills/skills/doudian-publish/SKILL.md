# 抖店发品存草稿

只存草稿箱，商品状态一律「下架」，绝不提交审核或上架；发布由用户在抖店后台自己确认。

## 步骤

1. 选账号：按 `ecommerce-accounts` 技能的规则选目标抖店的商家账号；`<店铺名>` 用 `dsh-ecommerce accounts` 里该账号的 `store`。运行 `dsh-ecommerce memory` 看公司记住了什么。调用 `load_workspace_dependencies` 取 `node` 路径；下面的脚本都相对本技能目录，每条命令一次 bash 调用。
2. 定类目：`"<node>" "<本技能目录>/scripts/doudian-publish.mjs" resolve --account <账号 id>` 加一个来源：
   - 记住过产品线就先用 `--line <产品线>`；
   - 否则 `--keyword <商品名>`（抖店类目搜索），搜不准时用 `--image <主图文件> --title <标题>`（抖店按主图和标题推荐）；
   - 用户给了类目 id 就 `--cat <类目 id>`；要逐层看就用 `children [--parent <类目 id>]`（只列店铺已开通的类目）。
   只能用店铺已开通的类目。除了用户给的类目 id 和记住的产品线，候选类目都要请用户确认；确认后用 `dsh-ecommerce remember` 记下产品线的类目（平台写 `doudian`；同一产品线在每个平台各记一个，不影响别的平台）。用户说记住的类目不对时，用 `{"forget": {"categories": [{"line": "<产品线>", "platform": "doudian"}]}}` 只删这个平台的，再重新定类目。`--line` 说只在别的平台记过时，按商品名或主图找抖店类目。
3. 读字段规则：`... rules --account <账号 id> --cat <类目 id>`，得到 `抖店发品/字段规则_<类目 id>.json`。文件里的 `qualificationImages` 是店铺资质库里每份资质的图片链接（资质名只是上传时间，要看图分辨）。
4. 整理素材：用 `ecommerce-product-draft` 技能（`draft` 加 `--rules <上一步的文件>` 和 `--store <店铺名>`）。答案文件里除了标题，还要写：
   - 类目属性按字段规则里的名字写，有可选值的按原文写（如器械所属分类「二类」）；注册号只写用户或店铺资料给的，不编造。
   - `资质：医疗器械注册证` 等资质：只能从字段规则列出的店铺资质库里选一份，写它的名字；不知道选哪份就把各份的图片链接列给用户，请用户在卡片里选，不要自己猜。
   - `运费模板`、`现货发货时间`：按规则里的选项写。
   - `商品重量（克）`：由用户或店铺资料给出；运费模板按重量计费时必填，包邮模板可以不填。
   - `参考价（元）`：选填；要设就必须同时给 `参考价凭证类型`（按规则里的选项）和 `参考价凭证图（素材文件）`（素材文件夹里凭证图片的相对路径，如吊牌或官网价格截图）；参考价不能低于最高售价，也不能达到它的 10 倍。用户没给参考价和凭证时，在卡片里问用户要不要设、请用户把凭证图放进素材文件夹，不要自己编。
5. 确认卡片：先在消息里把草稿逐项列给用户——图片各几张、SKU 表（名称、编码、售价、库存、SKU 图）、每个类目属性和资质的值与来源、运费模板、发货时间、重量、参考价、还缺什么，并说明会以「下架」状态存进草稿箱。然后用提问卡片问「确认保存到 <店铺名> 的抖店草稿箱吗？（商品状态：下架）」，选项按下面的顺序（卡片默认选中第一项，所以第一项不能是保存）：
   - **修改某项**（用户在卡片里写要改什么，你改答案文件后重跑第 4 步，再回到第 5 步）
   - **重新生成标题**（你重写商品标题后重跑第 4 步，再回到第 5 步）
   - **补缺失**（问用户缺的内容，比如参考价、重量、资质选哪份；素材要用户放进文件夹，不拿别的图顶替）
   - **取消**（什么都不保存，告诉用户已取消）
   - **一键认可，保存到草稿箱**
   这张卡片和之后任何会导致保存或重试保存的卡片都**不要给任何选项标「推荐」/(Recommended)**。清单里还有「缺失」「不符合」时先补齐，不要保存。
6. 用户选「一键认可」后保存：`"<node>" "<本技能目录>/scripts/doudian-publish.mjs" save --account <账号 id> --draft <商品草稿.json> --rules <字段规则.json> --confirmed [--stock <每个 SKU 的库存>]`。`--confirmed` 只能在用户这一轮选了「一键认可」之后加。bash 超时设为 600000 毫秒。脚本保存前会先查草稿箱和商品列表有没有同一商品（同标题，或 DSH 存过的同一组 SKU 编码），有就不保存。
7. 回复：商品 ID、标题和草稿箱链接，说明商品状态是「下架」、在草稿箱里，提醒用户到抖店后台确认后自己提交发布。

用户只想知道店里有没有这件商品时，运行 `... check --account <账号 id> --draft <商品草稿.json>`，它只查不改。

## 结果与退出码

- `0`：已保存并在草稿箱里查到；或店里已有同一商品，没有重复保存（输出会写明）。
- `64`：还不能保存（列出缺失、不符合、待确认的项，比如缺参考价或重量），或参数错误。补齐后再走第 5 步。也可能是上次保存结果不明：请用户到抖店后台草稿箱和商品列表确认没有这件商品；用户明确说没有后，才能在 save 后面加 `--unknown-checked`。
- `3`：账号需要重新登录。
- `1`：抖店没有保存（列出原因），或保存后结果不明，或商品出现在「售卖中」（请用户立即下架）。**不要自动重试**；把原话告诉用户。

## 规则

- 保存只能用本技能的 `doudian-publish.mjs save`。**不要修改、复制或另写脚本，也不要自己调用抖店的接口或操作发品页去保存、提交**；脚本报错就把原话告诉用户，由用户决定，不要自己「修好再试」。
- 绝不提交审核或上架，商品状态只能是「下架」；不改店里已有的商品和草稿。
- 用户选「取消」或没有明确认可时，什么都不保存。
- 失败或结果不明时不自动重试，不换店。
- 模型生成的内容在用户认可前不算数；资质只能从店铺资质库里选，由用户确认。

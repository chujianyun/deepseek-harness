# 单品全量采集和报告

采集公开商品页的数据，生成单品报告的事实层（统计 + 原文引用）。只用买家账号，由 DSH 自动挑选；不使用商家账号，不改动任何东西。

## 步骤

1. 取 Node：调用 `load_workspace_dependencies`，用它返回的 `node` 路径运行脚本（员工电脑不需要另装 Node 或 Python）。
2. 在用户的工作区里，用一次 bash 调用运行（`scripts/` 相对本技能目录），并把这次调用的 `timeoutMs` 设为 600000：采集期间买家号由这次调用占用，调用结束占用就结束。

   ```sh
   "<node>" "<本技能目录>/scripts/item-report.mjs" <商品链接或 id> [更多商品…]
   ```

   - 不需要先运行 `dsh-ecommerce`：脚本自己调用 `dsh-ecommerce buyer`，由 DSH 挑选可用、当天用量最少的买家号。
   - 默认读 问大家 100 条、评价 200 条、追评 100 条、每个负面标签 100 条，接口调用之间间隔 4.5~6 秒，一个商品约 1~2 分钟。用户明确要更多时才用 `--questions`、`--reviews`、`--appends`、`--per-tag` 调大；越多越慢，风控风险越高。
   - `--out <目录>` 指定输出目录，默认工作区下的 `天猫报表/`，每个商品一个 `单品_<id>/` 目录。
3. 读脚本打印的摘要，再打开 `报告.md`（必要时看 `facts.json`、`reviews_negative.csv`），向用户说明：用了哪个买家号、每个商品采到了什么、主要发现。结论只能基于报告里的统计和原文，引用要逐字，注明样本口径（例如「主列表样本 200 条，非全量」）。

## 结果与退出码

- `0`：全部商品采集完成。
- `4`：中途停止，已读到的部分都已保存，报告里标明了「中途停止」。原因会写在最后：
  - 平台出现风控（滑块或身份验证）：如实告诉用户已立即停止。**不要重试，不要去点验证，不要换买家号，今天不要再用这个买家号。**
  - 买家号今天的页数不够或都在冷却：告诉用户哪些商品没采、明天再来，或请用户在 DSH 设置 → 电商账号增加买家号。
- `3`：买家号需要重新登录：请用户到 DSH 设置 → 电商账号重新登录。
- `1` / `64`：其他失败或参数错误，把脚本的说明原样告诉用户。

## 规则

- 只读：只查看公开页面，不下单、不加购、不收藏、不评论。
- 不要自己再打开商品页或别的页面：每打开一个页面都计入买家号当天的额度。

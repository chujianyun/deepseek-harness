# 吉客云组合装

只按用户确认过的明细创建；不编造编号、条码或价格。一次只建一个组合装。

## 准备

- 先运行 `jackyun docs list`。找不到 `jackyun` 命令时，告诉用户到 MO WorkAI 的「连接器」页打开「公司提供的工具 → 吉客云」；那里没有吉客云就请公司管理员开通。不要让用户提供 AppKey 或密钥。
- 每次调用都是 `jackyun api call --method <接口> --json '<JSON>'`，或把 JSON 写进文件后用 `--file <文件>`。**Windows 上一律用 `--file`**：PowerShell 会改掉 `--json` 里的引号。
- 要看接口有哪些参数，运行 `jackyun docs get -m <接口>`。

## 步骤

1. **收集清单**：每个子件要有货品编号、货品名称或条码之一，以及数量；组合装要有名称和货品编号（用户没给编号就问，不自己编）。条码、分摊单价、计量单位用户给了才写。
2. **逐个查子件**：`jackyun api call --method erp.storage.goodslist --json '{"goodsNo":"<编号>","pageSize":50,"maxSkuId":"0"}'`；按名称查把 `goodsNo` 换成 `goodsName`，按条码查换成 `skuBarcode`。在结果的货品行里看 `goodsNo`、`goodsName`、`skuName`（规格）、`skuBarcode`、`skuCode`、`unitName`、`retailPrice`、`isPackageGood`。
   - 没有查到：告诉用户哪个子件查不到，请他给准确的编号或条码，不要猜。
   - 查到多个（同名多款或一个货品多个规格）：把候选的编号、名称、规格、条码列出来请用户选。
   - 查到的本身是组合装（`isPackageGood` 为 1）：提醒用户，问是否仍要放进新组合装。
3. **看组合装是否已存在**：`jackyun api call --method erp-goods.goods.listgoodspackage --json '{"goodsNo":"<组合装编号>","pageIndex":0,"pageSize":50}'`。结果里有同编号的组合装时，记下它现在的子件，在确认时告诉用户「这个编号已有组合装，创建会覆盖它」，并对比原来和新的子件。同名不同编号的也要提醒，吉客云按编号或名称都可能更新已有货品。
4. **列明细表**：表头为 子件编号 / 名称 / 规格 / 条码 / 数量 / 单位 / 分摊单价；再写组合装的名称、编号、条码（如有）。分摊单价没给就留空；你按零售价算出的建议值要标「建议」，请用户确认。
5. **确认卡片**：用提问卡片问「确认在吉客云创建组合装 <名称>（<编号>）吗？」，选项按这个顺序（卡片默认选中第一项，所以第一项不能是创建），**不要给任何选项标「推荐」/(Recommended)**：
   - **修改某项**（用户写要改什么，改好后回到第 4 步）
   - **取消**（什么都不创建，告诉用户已取消）
   - **确认创建**（会覆盖时写成「确认创建（覆盖已有的 <编号>）」）
6. **创建**（只在用户这一轮选了「确认创建」之后）：把参数写进文件，如 `吉客云组合装/<组合装编号>.json`：
   ```json
   {
     "goodsNo": "<组合装编号>",
     "goodsName": "<组合装名称>",
     "skuList": [{ "skuBarcode": "<组合装条码，没有就去掉 skuList>" }],
     "packageSkuList": [
       { "skuBarcode": "<子件条码>", "goodsAmount": "<数量>", "sharePrice": "<分摊单价，没有就去掉>", "unitName": "<单位，没有就去掉>" }
     ]
   }
   ```
   子件优先用条码 `skuBarcode` 指定；没有条码时改用 `outSkuCode`（货品行里的 `skuCode`）；两样都没有就告诉用户这个子件没法放进组合装。然后运行 `jackyun api call --method erp.packagegoods.import --file <文件>`。
   - 命令以状态 3 退出并说会覆盖已有货品：如果第 5 步用户已经确认了覆盖，就加上 `--confirm-overwrite` 再运行同一条命令，DSH 会再请用户批准一次；用户没确认过覆盖，就停下来把情况告诉用户，回到第 5 步。
   - 返回的 `code` 不是 200：把 `msg` 原样告诉用户，不要自己反复重试。
7. **回查核对**：再查一次 `erp-goods.goods.listgoodspackage`（按组合装编号），把吉客云里的子件和数量与明细表逐项对比，告诉用户创建结果、组合装编号，以及有没有对不上的地方。

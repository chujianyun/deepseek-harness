# 商品素材整理

发品前把素材整理成商品草稿，并告诉用户还缺什么、哪些要确认。每个值都标明来源：素材原值、店铺资料、沿用旧商品、模型生成、发品规则。

## 步骤

1. 取 Node：调用 `load_workspace_dependencies`，用它返回的 `node` 路径运行脚本（`scripts/` 相对本技能目录）。
2. 清点素材：`"<node>" "<本技能目录>/scripts/product-draft.mjs" inventory --folder <素材文件夹>`。脚本列出每张图归到哪一类及理由、每张表每一列对应的字段。
3. 补判规则判不了的：
   - 「待判断」的图片：能看图就看图判断，看不了就把文件名列给用户问。
   - 「未识别」或对错的列：按示例值判断它是哪个字段（`index`/`name`/`code`/`count`/`price`/`stock`/`unitPrice`，不用的写 `ignore`）。
   - SKU 图和 SKU 对不上时：看图中文字判断属于哪个 SKU，判断不了就问用户。
4. 要发到天猫或淘宝时，先用 `tmall-publish-category` 技能定类目并读字段规则，得到 `字段规则_<类目 id>.json` 的路径。
5. 在工作区写答案文件（如 `发品草稿/答案.json`）：

   ```json
   {
     "columns": { "到手价": "price" },
     "images": { "素材图/场景图.jpeg": "other" },
     "skuImages": { "sku图/a.png": "SKU1" },
     "values": {
       "商品标题": { "value": "…", "source": "模型生成" },
       "商品卖点": { "value": "…", "source": "模型生成" },
       "导购标题": { "value": "…", "source": "模型生成" },
       "产地": { "value": "大陆", "source": "店铺资料" }
     }
   }
   ```

   - 图片类别：`main`（1:1 主图）、`main34`（3:4 主图）、`white`（白底图）、`transparent`（透明素材图）、`detail`（详情图）、`sku`（SKU 图）、`other`（不用）。
   - `商品标题`、`商品卖点`、`导购标题` 由你根据素材（SKU 名称、文档、图中文字）生成，来源写 `模型生成`。天猫标题不超过 30 个汉字（60 个字符宽度），不用「最」「第一」等绝对化用语。
   - `values` 的键用字段规则里的字段名（如「产地」「生产企业」「注册证号」）。只写用户给过或店铺资料里有的值，来源写 `店铺资料`；沿用本店同产品线已有商品的值，来源写 `沿用旧商品`。注册证号、械字号等资质信息不要编造。
6. 生成草稿：`"<node>" "<本技能目录>/scripts/product-draft.mjs" draft --folder <素材文件夹> --answers <答案文件> --rules <字段规则文件>`。没有字段规则时省略 `--rules`，只整理不检查。脚本保存 `发品草稿/商品草稿.json` 和 `发品草稿/待确认清单.md`。
7. 回复用户。最终回复必须直接写出下面这些内容，不能只给文件链接或只说「已生成」：
   - 各类图片的数量（1:1 主图、3:4 主图、白底图、透明素材图、详情图、SKU 图，以及不使用的其他素材）；
   - SKU 表（名称、编码、只数、价格、对应的 SKU 图）；
   - 待确认：模型生成的每个值，请用户确认或修改；
   - 待店铺确认的声明：原文照录，不替用户勾选；
   - 缺失和不符合的每一项，以及要用户补什么；
   - `商品草稿.json` 和 `待确认清单.md` 的位置。

## 结果与退出码

- `0`：成功。草稿里有缺失或不符合的项也返回 0，按清单告诉用户。
- `64`：参数错误、素材文件夹不存在，或答案文件、字段规则文件格式不对；按提示改正后重跑。
- `1`：其他失败，把脚本的说明原样告诉用户。

## 规则

- 缺少的素材（例如没有详情图、某个 SKU 没有图）只能标为缺失并请用户补充，不要拿别的图片顶替。
- 模型生成的内容一律标「待确认」，用户确认前不当作最终值。
- 只读本地文件，不发布、不保存草稿、不改动店铺。

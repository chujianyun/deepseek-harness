# 天猫日报取数

给日报填表用的取数技能：两个脚本各用一个账号，直接调用平台页面自己的数据接口，不点击页面，也不改动任何设置。

## 步骤

Windows 上命令行是 PowerShell：以带引号的路径开头的命令前要加调用符 `& `，例如 `& "<node>" "<本技能目录>/scripts/…" …`，否则 PowerShell 不会执行它。

1. 选账号：按 `ecommerce-accounts` 技能的规则运行 `dsh-ecommerce accounts`。天猫脚本用 `platform` 为 `tmall`、`kind` 为 `merchant` 的账号；云台脚本用 `platform` 为 `yuntai` 的账号。调用方（如日报编排技能）指定了店铺时，按店铺名选；有多个可选又没有指定时先问用户；没有可用账号时停下，请用户到 DSH 设置 → 电商账号登录。
2. 取 Node：调用 `load_workspace_dependencies`，用它返回的 `node` 路径运行脚本（员工电脑不需要另装 Node 或 Python）。
3. 每个脚本单独用一次命令行调用运行（`scripts/` 相对本技能目录）：

   ```sh
   "<node>" "<本技能目录>/scripts/tmall-daily-figures.mjs" --account <天猫账号 id> --date <YYYY-MM-DD> --item MO=610081277604 --item 003=524565741530
   "<node>" "<本技能目录>/scripts/yuntai-daily-figures.mjs" --account <云台账号 id> --date <YYYY-MM-DD> --self-keyword ML
   ```

   - `--date` 必填，只能是已经过去的日期（北京时间）。
   - `--item <名称>=<商品ID>` 可写多次，取这些商品当天的支付金额；不写就只取全店。
   - `--self-keyword <关键字>` 账户名含这个关键字的云台账户算作自投，汇总它们的花费与成交；不写就不取自投。
4. 需要保存结果时，把脚本输出原样写进工作区的 JSON 文件，不要改动里面的数。

## 输出

成功时脚本输出一行 JSON：`{"platform", "accountId", "store", "account", "data": {"date", "platforms": [...]}}`。`platforms` 每项是 `{"platform", "date", "metrics", "missing", "notes"}`：

| 脚本 | platform | metrics（元；退款率为比值） |
|---|---|---|
| 天猫 | 生意参谋 | `全店支付金额`、每个 `--item` 的 `<名称>支付金额` |
| 天猫 | 万相台 | `关键词推广花费`、`关键词推广成交`、`人群推广花费`、`人群推广成交`、`货品全站推花费`、`货品全站推成交` |
| 云台 | 健康品牌云台 | `三方外投消耗`、`三方外投有效GMV`、`三方外投总GMV`、`三方外投退款率`；有 `--self-keyword` 时再加 `自投花费`、`自投有效GMV`、`自投总GMV` |

- 某项为 `null` 时，`missing` 里写了原因（例如平台当天数据还没出来、商品排行里找不到这个商品）。如实转述，绝不估算、绝不用别的日期替代。
- `notes` 是口径说明和自检结果：生意参谋写明店铺与统计日；万相台写明 1 天累计口径；云台写明各媒体消耗及其合计是否与总计一致，以及算作自投的账户与各自消耗。
- 万相台成交按 1 天累计归因，和万相台报表页默认的 15 天累计不同；生意参谋全店支付金额与首页「数据概览 → 日」的支付金额一致。

## 退出码

- `0`：成功（个别平台的数还没出来时也是 0，对应项为 null）。
- `3`：账号需要重新登录。请用户到 DSH 设置 → 电商账号重新登录，不要换别的店铺。
- `1` / `64`：其他失败或参数错误，把脚本的说明原样告诉用户。云台出现别的店铺、生意参谋页面不是这家店时也是 `1`，不取数。

## 规则

- 只读：不要修改出价、预算、计划或任何店铺设置。
- 一次只用调用方指定的账号；失败时不要自动换店。

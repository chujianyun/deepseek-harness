# Agent Note: 整窗外壳背景 slot

Status: implemented

[English](2026-08-18-shell-background-slot.md) | 中文

## 问题

视觉插件需要一种受支持的方式，在侧边栏、会话栏和详情栏之后渲染连续背景。注册到单个栏会割裂图像，而 DOM 注入依赖私有标记，无法进入普通插件的 dispose（资源释放）生命周期。主题 token 覆盖可以让界面表面变透明，却不能拥有图像或其他可渲染背景。

未安装背景插件时，外壳必须保持原有外观。背景贡献还必须位于各栏内容和交互控件之下；移除插件时，应当无需与布局或主题实现协调就恢复原有背景。

## 决策

`ui-layout` 在拥有 AppFrame 的同一次注册中，将 `shell.background` 声明为 root scope（根作用域）的 `single` slot。AppFrame 在三栏之前渲染一次该 slot，并将其放入绝对定位、铺满 frame 的图层。该图层不接收指针事件。侧边栏、会话栏和详情栏渲染在它之上；拖动手柄保持在各栏之上；`shell.overlay` 仍是 frame 内的最高层。

该 slot 只拥有渲染后的背景内容。AppFrame 保留现有的 `--dsw-alias-bg-base` 背景，因此 slot 为空时不会产生视觉变化。普通 slot 生命周期会在插件或 AppFrame 声明被 dispose 时移除贡献。原有背景会立即显现，不需要 DOM 清理协议，`ui-layout` 也不修改主题。

由于该 slot 是 `single`，安装第二个背景提供方会替换第一个提供方的渲染权限，而不是组合两个背景。若提供方还修改界面透明度，它必须单独拥有这些主题覆盖，并通过自身插件生命周期将其 dispose。

## 备选方案

**向 AppFrame DOM 注入背景元素。** 该方案依赖私有选择器和顺序，绕过 slot 所有权账本，还会让重载与 dispose 清理变成提供方专属逻辑。

**只用主题 token 表达背景。** token 可以控制颜色和半透明表面，却不能渲染图像、保留图像加载状态或提供普通 React 生命周期行为。

**每栏增加一个背景 slot。** 分离的占用方无法保证图像跨越持续变化的栏宽后仍然连续，还会重复加载、定位和 dispose 工作。

**使用 list slot。** 堆叠多个相互独立的整窗背景会使不透明度和所有权顺序含糊不清。一个提供方应当拥有完整背景；其他视觉图层应放在该提供方内部，若属于前景 UI，则放入 `shell.overlay`。

## 影响

背景插件无需访问 AppFrame 内部实现即可获得稳定的渲染位置。slot 为空或被 dispose 时会精确保留已发布主题，指针输入也会继续到达各栏和外壳控件。单占用规则避免意外堆叠背景，并使提供方替换具有确定性。

外壳现在多维护一个绝对定位图层和一个公开 slot key。若背景提供方让原生界面表面变透明，它必须协调自身的渲染背景与主题覆盖生命周期；布局包不会推断或应用透明度。

## 验证

`ui-layout` 的 apply spec 断言 root-scoped single 声明及其随所属 fiber 移除。AppFrame spec 断言背景图层在各栏之前渲染并位于 `shell.overlay` 之下；现有布局交互 spec 会在新图层存在时继续覆盖拖动手柄与各栏行为。

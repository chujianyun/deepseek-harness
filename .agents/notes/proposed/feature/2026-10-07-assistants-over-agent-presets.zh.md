# Agent Note: 叠在 Agent preset 之上的智能体

Status: proposed

[English](2026-10-07-assistants-over-agent-presets.md) | 中文

## 问题

桌面版用户希望有具名的工作角色，就像 Accio Work 的「智能体」：日常助手、电商管家，各有自己的头像、人格、模型，以及它要用的 Skill、连接器和知识库。DSH 已经有引擎层面的部件（Agent preset 选择工具、提示词和 Skill；`dsh-persona` 给单个 agent 设置自己的系统提示词人设），但没有一个用户能创建、命名、编辑、并在开新会话时选择的东西。这种角色和 preset 是什么关系、它的定义存放在哪里，决定了两套机制会不会争抢同样的选择，也决定了这份定义以后能否共享、导出，或由模型写回。

## 提案

[智能体](../../../../docs/glossary.zh.md#assistant)**叠在** Agent preset **之上**：它指定一个 preset 作为能力底座，再加上自己是谁、带什么。

- **工具仍由 preset 决定。** 智能体选择一个 preset（标准、极简、PTC 等），从不逐个开关工具，所以工具选择只有一套机制。
- **核心文件定义它是谁。** 每个智能体有四份 Markdown [核心文件](../../../../docs/glossary.zh.md#assistant-core-files)：身份、人格、用户信息和工作方法。它们通过作用于该会话 agent 的 persona 机制交给模型，并且每轮都重新读取，改动从下一轮生效。
- **能力子集。** Skill、连接器和知识库各自是「全部（跟随全局）」或「仅选中」；选中的项目之后被卸载时直接失效。
- **一个智能体一个目录，按租户存放。** 智能体是一个存放配置和核心文件的目录，放在当前 [Hub 登录](../../../../docs/glossary.zh.md#skill-hub)所在的租户下，因为它带的连接器和知识库本来就属于该租户。
- **会话创建时绑定。** 会话在创建时绑定一个智能体，之后不再更换；智能体被删除后，它的会话仍可查看和继续使用，只是不带人格。
- **模板只是起点。** 内置日常助手和电商管家两个[智能体模板](../../../../docs/glossary.zh.md#assistant-template)；首次启动时按日常助手创建默认智能体。

## 考虑过的替代方案

### 为什么不用智能体取代 Agent preset？

preset 是声明式的 Cordis 组合，profile、创造模式和 Web 的 preset 选择器都已经依赖它。为了加上身份而替换它，等于重写一套正常工作的机制，而身份是另一个关注点。

### 为什么不为每个智能体生成一个 preset？

生成的 preset 会为每个智能体复制一遍底座 preset 的插件行，以后底座的每次改动都要同步到每份副本。引用底座则让工具只有一个事实来源。

### 为什么不把智能体存进 profile 配置？

配置项适合短值，不适合用户要编辑的几页 Markdown。每个智能体一组普通文件，在 DSH 之外也能阅读和编辑，也正是以后导出导入、团队共享和模型写回记忆所需要的形态。

## 验收标准

- 用某个智能体创建的会话，把该智能体的核心文件作为人设发送，并且只带上其能力子集允许的 Skill、连接器和知识库。
- 编辑核心文件后，进行中的会话从下一轮起使用新的人设。
- 在一个租户中创建的智能体，登录另一个租户后不可见。

## 风险

- **会话中途人设变化。** 核心文件每轮重新读取，会话进行中的改动会让模型行为突然变化。
- **能力静默缺失。** 「仅选中」子集中被卸载的项目会无报错地消失，详情页必须标出来。
- **人设遮蔽部署级人设。** 智能体的人设会替换该会话的部署级人设，所以放在那里的部署品牌文本需要通过其他方式传给智能体。

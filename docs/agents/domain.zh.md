# 领域文档

[English](domain.md) | 中文

工程 skill（技能）使用一个词汇表和一个仓库级 ADR 目录。这些规则供 agent（智能体）读取文档时使用，不属于产品文档。

## 探索前读取

根目录 `GLOSSARY.md` 存在时，先读取它；`docs/adr/` 存在时，读取其中的相关决策。任一项不存在时，直接继续，不提示缺失，也不要在初始化时建议或创建空文件。领域建模会在术语或决策确定后创建这些文件。

同时参阅[架构概览](../architecture.zh.md)、相关子系统和包的参考文档，以及当前 [Agent Notes](../../.agents/notes/README.zh.md)。现有 Agent Notes 是其决策的维护位置，不要在 ADR 中重复记录。遵循 Agent Note 的生命周期规则，不要将已归档记录视为当前依据。

## 布局

使用单一上下文布局：

```text
/
├── GLOSSARY.md
└── docs/
    └── adr/
        ├── 0001-<decision>.md
        └── 0002-<decision>.md
```

本次初始化不创建根目录 `GLOSSARY-MAP.md`，也不为各个包创建独立词汇表和 ADR 目录。

## 术语

问题标题、提案、假设和测试应使用词汇表中的术语。术语缺失时，先检查相关包和子系统文档，不要自行创造同义词。双语术语遵循[现有术语参考](../i18n/terminology.md)。将真实缺口记录为领域建模的待处理事项，不要凭推测补充。

## 决策冲突

提案与现有 ADR 或当前 Agent Note 冲突时，明确指出冲突记录，并说明为何应重新讨论该决策。不要默默覆盖既有决策。
